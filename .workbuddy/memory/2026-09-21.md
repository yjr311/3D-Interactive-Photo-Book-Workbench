# 2026-09-21 · 第十五轮：牛皮纸「贴纸只能往左上拖」

## 用户报的
> 「有个bug这个牛皮纸，插入的贴纸无法往右以及往下拖拽」

## 根因（实测，不是推测）
`photoRect` 这个中间量**串了坐标系**。牛皮纸模版是先 `translate(W/2,H*.45); rotate(-.028)`
再 `c.paint(-pw/2,-ph/2,…)`，`drawFit` 量出来的是**调用点的局部坐标**：`-345.6,-460.8`
（960×1280 下 3/4 在画布外、中心压在画布左上角）。它被当成**画布像素**用 →
面板 `clamp((px-rc.dx)/dw,0,1)` 往右/往下算出来超 1 → 被夹住 → 纹丝不动。
贴纸 `(.5,.5)` 被画在画布 `x=-1.1`（画布左边缘外面）。

## 改了什么（core.js，四处）
1. 新增 `rectThruM(rc, m)`：四角过 CTM 取外接矩形；**单位矩阵原样返回**；**不返回矩阵**。
2. `paintPhoto`：先与**画框**求交（cover 溢出的不算照片），再过 CTM。
3. `cx.paint` / `cx.declare` 的"面积最大者胜"加 `1e-6` 容差；新增 `declare(x,y,w,h)`。
4. `duotone.draw()` 里 `c.declare(m,H*.1,W-m*2,H*.66)` —— 它不调 `c.paint`，必须申报。

实测矩形（改前 → 改后）：
`kraft -345.6,-460.8,691.2,921.6 → 123.8,182.5,712.4,787.1`；
`postcard 52.8,-158.4,854.4,1139.2 → 52.8,52.8,854.4,716.8`；
`neon 101.8,20.5 → 101.8,156.2`；`minimal 192,128,576,768 → 192,192,576,640`；
`cinematic 0,0,960,1280 → 0,172.8,960,934.4`；`polaroid 72,-2.9 → 72,87`；
`duotone 0,0,960,1280 → 96,128,768,844.8`；`grid9 255.8,21.8 → 352.6,184`。
牛皮纸四向真实鼠标拖拽：瞄 `0.85/0.5`→`0.849/0.5`、`0.5/0.85`→`0.503/0.849`（改前这两条**一动不动**）。

## 一个必须纠正的旧记忆
我原先记的是"九宫格三格面积**按位完全相等**，严格 `>` 让浮点噪声裁决平局"。
实测 **连渲 12 次同值** —— 它是**确定的**。真机制是面积**差在 1e-6 以下**，
"比前者大亿分之几"就胜出，赢家由**舍入**决定。所以"连渲 N 次对比"抓不到它。
隔离实验（`_tolon` 只去容差 / `_nointer` 只去求交 / `_before` 全去）才把四个改动各自的靶子分清。
