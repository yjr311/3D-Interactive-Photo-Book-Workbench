# 2026-09-18

## 光匣 LUMEN 第六轮：让模版真的出现在成书里

用户原话：「现在好看很多，但我选择的模版不会显示在成书那，那我这个模版功能做了干嘛呢，
想办法成书要兼容模版图片和兼顾好看」。

### 先承认：上一轮的设计取舍做错了

第五轮为了「好看」，把书页的画面一律换成 `plain`（干净照片），
结果用户逐张分配的模版**在成书里完全看不见** —— 模版功能形同虚设。
用户的直觉是准的。

**真正的丑源不是"用了模版"，而是模版那句全局同一行的文字。**
`state.opts.title` 原本是一个常量 `'今日份'`，于是 28 页整整齐齐印了 28 遍，
下面再叠一行书本图注 → 同一种信息出现两次。
所以正确的修法是**让文字按照片取值**，而不是把模版扔掉。

### 改了什么

**① 模版文字改成占位符，按照片解开（这是本轮的核心）**
- `state.opts.title / sub / corner` 支持 `{name}` `{n}` `{nn}` `{total}` `{tpl}`；
  出厂默认改成 `title='{name}'`、`sub='{n} / {total}'`、`corner='NO.{n}'`。
- 新增 `resolveTokens(t,im)` / `ordOf(im)` / `totalOf()` / `optsFor(im)`；
  `generate()`、预览区、胶片带三处都走 `optsFor()` ——
  **预览里看到的那行字，就是成片与成书里会有的那行字**。
- 不认得的占位符原样留下（方便用户看出自己写错了）。

**② 新增 `state.book.art`：`'tpl'` 模版成品（默认）/ `'plain'` 干净照片**
- 内容页改用 `plateOf(im)`；封面 / 扉页 / 环衬仍然走 `artOf()`（干净照片）——
  那几页的排版是整套设计的，再叠一层模版外壳只会打架。
- 模版成品不是「原样铺满页面」，而是当**一张装裱好的印片**放进版心。
  实测几何：左/右 9.6%、上 8.2%、下 11.2%（下边略大于上边 = 传统装裱比例）。

**③ 消除"同一信息出现两次"**
- 新增 `plateHasText(im)` / `capWillDraw(im)`：模版自带题字时，书页**不再画图注**。
- 配套：**不画图注时画面箱体的下沿从「图注上方」放开到版心底**
  （`mat` / `two` / `sticker` 三处都调）。少了这一条，页面下方会留下一条
  谁也没用的空洞，又回到"没排完"的观感。`sticker` 没有图注时把画面略微放大并下移，
  和纸胶带跟着一起平移。

**④ 老存档定向迁移（不改这条，修复对老用户不可见）**
`PERSIST.restore()` 里只升级「原封不动等于旧默认值」的字段
（`今日份` / `2026 · LUMEN` / `NO.01`），用户自己改过的文字一律不动；
`book.art` 缺失时补默认。**没有换 KEY 版本号** —— 那会把用户辛苦做的
28 项逐项分配一起扔掉，为了修一行字不值得。

**⑤ 面板**：`版式` 区新增「书页画面」分段控件，note 按当前取值换文案；
模版文字区给出占位符清单 + 一行「当前选中照片的示例」。

**⑥ 成片过期提示（顺手补的关联缺口）**
模版成品是在 `generate()` 那一刻烧进画布的。用户改了某张照片的模版、
或改了模版文字/调色/规格，书里仍是旧图 —— 不说的话他又会以为"功能没生效"。
新增 `bookSig()` / `bookStale()`（签名 = opts + adj + spec.ratio/longEdge/fit），
`generate()` 时记下 `state._genSig`；`panel2` 的过期提示改成综合判断
（勾选数变化 / 某张照片模版变了 / 文字或调色变了），按钮文案改为「按当前设置重新生成」。

## 第七轮：面向「小女生群体」的优化升级方案（**只出方案，未改代码**）

用户原话：「效果差不多了，整体优化或者升级有没有什么好方案，改了之后会让用了非常不错，
能够吸引那些小女生群体来使用，先不急着修改，出一份优化升级方案给我看一下」。

产出 `光匣-优化升级方案.md`（v1 提案，11 节）。

### 核心主张（这是本方案最该记住的一条）

**不要改掉现在的高级感，而是给它加一层可切换的「氛围层」。**
现在的 UI 是「暗房 / 摄影集」路子（米白纸、衬线字、克制留白）——
这是产品唯一不像廉价拼图 App 的地方。为了少女向把底色换成粉底+贴纸，
结果大概率是"两边都不要"。
改成三层结构：**底色层（一行不动，资产）+ 氛围层（新增，token 化皮肤）+ 装饰层（新增，贴纸）**。
默认仍是现在的高级感，选氛围才变软萌。
好处：老用户不受伤；新用户第一屏从「选模版」（11 选 1）变成「选氛围」（6 选 1），
决策成本低一个数量级；「我把相册调成蜜桃色」本身就是可分享内容。

### 人群拆成四个动机（不写笼统画像）

记录型（plog，要快要竖版）/ 关系型（闺蜜本、纪念日，要双人）/ 收藏型（追星小卡、票根，要一页多张）/
表达型（氛围感，要滤镜字体贴纸音乐）。**建议第一批只做记录型 + 表达型** ——
这两类是小RED书上的主动发布者，传播效率最高。

### 本轮现场核实到的两个事实（写方案前必须查，不能凭印象）

1. **手机端基本不可用**：`head.html` 里 `@media(max-width:1000px){.rail{display:none}}`、
   `@media(max-width:800px){.panel{display:none}}` —— 素材栏与设置面板被**直接隐藏**。
   手机上只剩"导入→生成→翻书"一条窄通道，所有编辑能力够不着。
   而目标人群绝大多数在手机上 → **方案里列为最大风险项**（§6），
   给了两条路线：A 全量响应式（成本≈本轮全部 P0 之和）/ B 手机端走简版流程
   （导入→选氛围→一键成书→翻书→导出，成本约 A 的 1/3）。**我建议 B。**
2. **音效不是从零做**：已有 `Sound.swish()`（WebAudio 合成的翻页沙沙声）+ 开关按钮，
   所以"氛围音效"是扩展而不是新建，边际成本极低。

### 方案要点

- P0（**能分享**）：竖版导出（1080×1440 等）/ 分享长图 / 氛围皮肤 6 套 / 一键氛围成书 /
  文案库与心情标签。**第一批刻意不含贴纸** —— 贴纸是新数据模型，先跑通"立刻能发出去"。
- P1（能玩）：氛围音效 / 九宫格小卡页 / 日期戳票根 / 双人本 / AI 一键美化 / 双封面寄语。
- P2（能留住）：徽章打卡 / 搭配配方分享 / 冲印对接。
- **文案库直接接上一轮做的占位符机制**，新增 `{mood}` `{date}` `{days}`。
  坑：现成模版用 `ctx.fillText` 没有自动缩排，文案库必须配一个 `fitFont()` 统一处理溢出。
- **贴纸的数据模型**（四条决定）：归一化坐标 0..1（缩略图/预览/成片/书页共用一份数据）；
  贴纸要**烧进 art** 才能触发 `bookStale()`；按**照片名**持久化（与模版分配同一个自然键）；
  **手写走"预置笔迹 + 用户文字"，不做自由画笔**（成本三倍、产出更丑）。
- **视频导出的三种方案与取舍**：MediaRecorder+captureStream（简单、webm、iOS 有坑）/
  WebCodecs（可控、要自己写 muxer）/ 逐帧 PNG 打包 ZIP（零兼容问题、体积大）。
  **建议 C 保底 + A 默认**。录制必须确定性驱动（`anim.t0` 挪远未来 + 固定步长），
  这个坑项目里已踩过并写进 `canvas-page-flip` 技能。
- **少女感的纪律**：可爱来自比例与克制，不来自颜色浓度。要做（圆角 14–18px、
  字重 500/600、每套 skin 只 3 种字体、只 1 个强调色）；不要做（满屏粉、emoji 堆砌、
  彩虹渐变描边字、超 3 种字体、动版式、炫光粒子）。
- **可量化判据**：从打开到"第一张能直接发的图" 现在 4 步以上 → 目标 ≤3 步且第一步是"选氛围"；
  导出物竖版 1080×1440 ≤3MB 无需二次裁切；拿给 3 个目标用户不用教程用一次，
  看第一步会不会卡住。
- **顺带该修**：单文件 2.99MB（其中 ~2.8MB 是 28 张示例照片 base64）→ 降采样+webp，目标 <1.2MB；
  字体商用授权要逐个体检（法律风险，不是体验问题）；触屏手势只有 6 处 pointer 事件，
  双指缩放/滑动没有，手机端必须补。

### 待用户拍板三件事
① 手机端范围（A/B/不做，我建议 B）② 第一批动机（我建议只做记录+表达）
③ 视频导出档位（我建议 C 保底 + A 默认）。拍板后按第一批开工。

## 第七轮（下半）：第一批 P0 全部落地

用户拍板：**手机端先不做**（只做桌面流程）；**第一批只做「记录型 + 表达型」**；
**单文件压到 1.2MB 以下**；手写体商用授权"只用来展示不进商用，不用管"
（现场核实：项目里 **0 个 `@font-face`**，全部走系统字族角色，这个担心本来就不成立）。

按顺序关掉 5 个任务：体积压缩 → 氛围皮肤 → 文案库 → 竖版导出 → 一键氛围成书。

### ① 压缩管线（文件 2.99MB → **1.078MB**，余量 ~124KB）
- 示例照片降采样 + JPEG 重编码（`.workbuddy/tmp/embed_photos.py`）。
- `build.py` 加压缩：**terser 压 JS**（`-c passes=2 -m`，**toplevel 不混淆** ——
  顶层标识符与 `window.LUMEN` 才能存活），CSS 只去注释 + 行首缩进
  （**行内空白一律不动**，动到 `calc()` 里的加号就静默算错）。`--no-min` 出未压缩版调试。
- 教训：压缩是"以后每次加功能都要付的税"，所以要先把预算和校验做进构建脚本
  （build 结束打印 head/js/photos 三段 KB 与余量），而不是事后来一次大扫除。

### ② 氛围皮肤 7 套（`test_skin.mjs` 33/33）
- 皮肤**只给 token，不复制模版**。11 套模版打 `tone`（light/dark/photo/kraft），
  纸色从当前 skin 派生；11×7=77 份配置等于"改一个色号要改 11 处"，必然烂掉。
- 唯一写入点 `applySkin()` 必须**同时**改 `state.opts`（印片）与 `state.book`（书页/书封）。
  只改一边 = "书页变粉了、印片还是米色"的割裂，比不换还难看。
- `studio`（原味）刻意留空 `tplPaper/tplInk`，派生出来仍是空串 → 模版用出厂色，
  **默认观感与加皮肤之前逐字段一致**（用脚本比对过产物里的 SKINS 字面量）。
- 踩到的坑：第一版 6 套浅色皮肤的**书页纸色与模版纸色几乎同色**，像素采样显示
  7 套皮肤肉眼分不出来。修法：浅色皮肤的 `bookPaper` 统一比 `tplPaper` 深一档，
  并加断言 `lum(bookPaper) − lum(tplPaper) ≤ −6`。
- 亮色主题必须另取一档更深的强调色（`ui.light`），一套色打天下在浅底上对比度不够。

### ③ 文案库 + 心情标签（`test_note.mjs` 20/20）
- 6 组情绪 × 7 条，每条支持占位符 → 同一句套在 28 张上各自不同（不会 8 页重复一句）。
- **图注默认值从 `name` 改成 `note`**（没写退回照片名，老用户体验无变化）。
  不这么改的话用户写了半天文案书上一个字不显示 —— 就是上一轮「模版功能白做」的同一个坑。
- 改文案**不重出成片**，只重排书页（否则改一个字要等 28 张重渲染，没人愿意写）。
- `ordOf()` 的 bug：生成项 `id:'g0'` 走的是 `id` 而不是 `photoId`，导致生成项的序号
  恒为 1（`{n}` 全是 1）。改 `im.photoId || im.id`。
- 「套给全部」必须以"刚挑的那句"兜底：挑完自动跳下一张，"当前这张"这时候是空的，
  只看 `noteCur()` 按钮会莫名其妙拒绝执行。存 `state._noteLast`。

### ④ 竖版导出 + 分享长图（`test_export.mjs` 21/21）
- 4 档预设（小红书 1080×1440 / 故事全屏 / 方图 / 明信片）。**预设改的是成片本身的画幅**，
  不是导出时套白边 —— 后者得到"一张带白边的方图"，还要再裁，不算"能直接发"。
- `pageAspect()` 从 `spec.ratio` 解耦到 `book.ratio`：选 9:16 导出预设不能把整本书压成手机屏。
- 分享长图：1080 宽竖版 + 顶部书名日期 + 底部裁切安全区，去掉环衬/空白页，
  超 16000px 等比缩小。

### ⑤ 一键氛围成书（`test_auto.mjs` **48/48**）
- 四件事：套氛围 → 按推荐序列铺模版 → 自动挑封面（复用 `coverScore`）→ 生成。
  三处入口（首屏 / 逐张分配 / 选片成书），空舞台还提供「载入示例照片并一键成书」。
- 每套氛围带 `tpls`（4 套模版，7 套合起来覆盖全部 11 套）与 `rec.layout` + `alts`。
- 「换一版」只换排法（序列起点 +1、封面顺延、版式在推荐两档间轮换），
  **不换氛围、不换照片** —— 氛围是用户选的，被随机掉就是背叛。
- ⚠ **铺模版的顺序必须和 `generate()` 里 `filter(picked)` 的顺序完全一致**，否则
  "第 3 张"在成片里对不上 `generated[3]`，逐张改模版会改错人。这条已写成断言。
- 一张都没勾时默认"全部做进去"，但按钮文案先说明、`pickAll:false` 时明确拒绝。
- 关键设计原则：**一键功能不能有后门**。它只是把面板上现有的动作替用户点了一遍，
  点完照样能逐张改 —— 所以「逐张可控」这个前提没有被破坏。

### ⑥ 顺带修掉一个真 bug：`.note` 类名撞车（这条最值得记）
`p.note`（说明段落，面板里 14 处）与 `.notes .note`（文案候选按钮）**共用了 `.note`**。
按钮样式里有 `white-space:nowrap` + `overflow:hidden` + 边框 + padding，
而 CSS 里光写 `.note` 会把说明段落一起命中 ——
**面板上每一段说明都被截成了一行**（`scrollWidth` 1172px 挤在 283px 里）。
症状极具迷惑性：不报错、不溢出、只是文字从句中消失，肉眼像"文案本来就这么短"。
修法：按钮样式收进 `.notes .note`；说明段落显式声明 `white-space:normal` + 去框 + 换行。
`test_auto.mjs` 里加了 4 条守卫（A45–A48）。
诊断手法（可复用）：对可疑元素量 `getComputedStyle().whiteSpace/overflow` 与
`scrollWidth > clientWidth` —— 后者为真就是被截断了。

## 第七轮修订：材料/质感层（用户验收后的返工）

### 用户原话（这轮的全部动机）
> 「这个氛围效果很一般啊，就是感觉单单纯纯的换了个色，没有任何质感，比如书面质感，
> 写实真实质感之类的，这个换一版功能用起来也很单一，看看能不能改好一些，不行就去掉吧，
> 不然实在没啥用」

判断：**不是氛围没用，是"氛围 = 一套配色"这个模型太薄**。所以补一层材料，而不是删功能。

### 加了什么
- `MATSETS` 7 套配方 = 封面料 + 内页料 + 题字工艺（deboss 压凹 / foil 烫金 / plain 素题）
  + tex/sheen/lit 倍率。料有 7 种：linen / canvas / kraft / laid / silk / leather / coated。
- `matTile(kind,seed)`：256×256 贴图过程生成，**确定性**（xorshift，同 seed 逐像素一致）
  且**可无缝平铺**（特征经 `at()` 在 ±256 四方向补画）。
- 三层渲染：底色（皮肤色号）→ 材料 tile（`paperGround`/`boardGround`）→ 光照
  （受光/背光、书沟阴影、纸边厚度 `pageEdge`）；封面另加漫射光 + 四角渐暗 + 板缘厚度。
- `pressTreat` 题字工艺、`plateSheen` 印片涂层。
- 面板里材料选择器，小样是**真材料**（92×30 canvas 直接调 `boardGround` 画），不是近似色块。
- 「换一版」从"挪模版顺序"升级为"换整本书的装帧"：材料 + 版式 + 序列起点 + 封面，四件一起换；
  仍不换氛围、不换照片（原本只换模版顺序，用户嫌"单一"）。

### 踩的三个坑（都留了回归守卫）
1. **丝绸贴图不可平铺**：4 条对角渐变铺满整张 tile，边界不连续 → 880px 书页平铺它三四次，
   每 256px 一条竖接缝（列均值跳变 26.8，是相邻列的 5.4 倍）。改成**整周期正弦**
   （波数取整数，周期正好等于 tile 边长）。
2. **判"可平铺"的度量本身错了两版**：
   - 用"接缝 vs 相邻列**均值**"会把帘纹纸每 4 行的正常大跳误判成接缝（laid 被判 ×3.62）；
   - 改成"接缝 vs **最大**跳变"时忘了把接缝那一对排除在基准外 → 比值恒 ≤1、永远放行。
   - 最终判据：**接缝跳变 vs 贴图内部（排除接缝本身）的最大跳变**，阈值 1.35。
   - 并加了**反向对照**（人为造整幅渐变的坏贴图，必须被判为"有接缝"×114）来证明检测器有牙齿。
     **检测器自己也要有测试** —— 否则"全绿"可能只是检测器坏了。
3. **封面二次叠印造摩尔纹**：封面会把 tile 叠两遍（第二遍 1.7× + 旋转）来搅掉平铺周期，
   对织纹/纤维是对的；但丝绸的"连续波"会互相干涉出**菱形格**（暗封面上一眼可见）。
   现在 `MAT_TWO_PASS=['linen','canvas','kraft']`，只对会露出周期的粗料做第二遍。

### 顺手修掉的测试侧盲点（都在 test_mat.mjs 里）
- 持久化 key 是 `lumen.prefs.v1` 且 `PERSIST.save()` **去抖 200ms** —— 写完立刻读会读到旧值。
- `pressTreat` 的工艺取自 `state.book.mat`（不是传给 `boardGround` 的那个）——
  取证脚本画样张时必须同步设状态，否则看到的工艺是错的。
- 真实鼠标点击前要 `scrollIntoView`，面板可滚动、小样可能在视口外，否则点空。
- 贴图是**带 alpha 的叠加遮罩**，直接对原始 rgb 求均值没有意义（未覆盖处是 0）；
  要叠到中灰底上看"明度偏移 ≤10 + 方差"。
- **材料是"装帧层"，刻意不烧进成片**（`bookSig` 不含 `book.mat`）：换材料只重排书页、
  不重新生成、也不判过期。留痕在书页/书封上，不在每张照片里。

## 第八轮：用户报"文案选了没效果"（图注抑制语义写错）

用户截图报障：面板选了文案，书页上一个字都没有。**这是真 bug，不是误报。**

### 根因（两层）

1. **`plateHasText()` 比的是"有没有"，不是"是不是同一句"**：
   原实现 `return !!im.title`。而 `generate()` 给每张成片都写了 `title: mo.title`（默认
   `opts.title='{name}'`），所以**每张印片都"有题字"** → 图注被无条件抑制 → 选什么都看不见。
   正确语义：`opts.title/sub/corner` 里有没有**和文案同一句**的字（去空白后逐字相等）。
2. **满版出血（`full`）版式里根本没有画图注的代码**：即使用户把抑制条件改对，
   满版页上依然一个字不出现。三处版式（mat/two/sticker）有 caption 分支，full 漏了。
   → 补上底部柔光带 + 白色文字，位置在页码之上。
3. 顺手把四处各自内联的"缩字号 → 截断"循环收敛成一个 `fitCap()`（超标先缩到下限，
   仍超长才截断加 `…`），避免以后改一处漏三处。

### 两个"假绿"测试（本轮最重要的教训）

- `test_note` N10 与 `test_book` B30 **在 bug 存在时是绿的** —— 所以 272 项全绿并没有拦住这个 bug。
  - N10 数的是"这一行有没有像素"（ink），可页面上照片和印片本来就有像素 → 恒真。
  - B30 断言的是**错的语义**（"印片有题字→不该画"），它把 bug 当前提固化了。
- 重写为**同页"有文案 vs 无文案"的带内像素差**（只量图注应该出现的那条带，
  不量整页 ink）。反向对照：把旧 `plateHasText` 用 `_mkold.py` 打回产物得 `_old_cap.html`，
  同一批断言跑上去**全挂**（capWillDraw 恒 false、四种版式带内差全 0）→ 证明新护栏有牙。
- 新增：N21（出厂默认配置下图注真的画出来）、N22/N23（不重复：印片已用 `{note}` /
  图注来源=照片名 时抑制）、N24（图注在底部带内）、N25（四种版式都画）。

## 第九轮：用户报"图注字体太板正、还跟右边不一样"

用户截图 + 一句反馈：**「显示的字体太板正了，不太好看还跟右边显示的字体不一样」**。

### 这一轮的特点：本机复现不了

- 本机（无头 Chromium）跑同一行代码，图注中文落到**宋体**；
  用户截图里那句是**等笔宽的黑体**（和界面同款），右页拉丁是 Georgia ——
  所以"跟右边不一样"是字面意义上的：左边中文黑体、右边拉丁 Georgia。
- **怎么钉住的结论**（两个动作）：
  1. **从截图反推显示比例**：8 个字占 101 px → 字号 ≈ 101/(8×1.14) ≈ 11.4 px
     → 与 880 画布之比 ≈ 0.50。然后用真实无头浏览器把窗口调到**同一比例**
     （window 1850×1100 → `BV.pw≈456`）截图对照。同尺度下：
     用户那句**没有一条细横**，本机那句**横细竖粗**。
  2. **对照实验**：把本机的宋体渲染过一遍 JPEG q60 再放大 —— 细横**仍然在**。
     于是"是不是剪贴板压缩把细节吃了"被排除。
- 中间还试过掩膜宽高比、像素纹理并列、原样/JEPG 双路比对，方向都对，但都不如
  **"同显示比例 + 真实浏览器截图"**这一条直接。

### 修法（图注字体不再靠浏览器兜底）

1. **字族按用途分角色**：`serif` 只给题字（封面/书名页/版权页/导出页眉）；
   新增 `cap` 给正文（书页图注，首选**楷体**）；`hand` 给手写体（贴纸版式）。
2. **开机位图探测** `fontOK(fam)`：同一个"中文 + 拉丁"样本，用该字族 vs
   一个绝对不存在的字族各画一遍，像素有差才算"装了"；`pickCJK` 挑第一个确实装了的。
   - 样本带拉丁是必须的：中文字族的 CJK 可能和系统默认中文一模一样
     （只看中文会把装了的判成没装）。
   - 全部验不出来时**不退给 `serif` 去猜**，明确退到界面同一套黑体。
   - 本机实测：`KaiTi/楷体/SimSun/宋体/FangSong/仿宋` = true，
     `Kaiti SC/STKaiti/Songti SC/STSong` = false（macOS 专用名，探测正确地说了"没有"）。
3. **面板把实际字族写出来**（"图注字体 楷体"）—— 这一行是这一轮排查时最缺的信息。
4. 楷体比宋体轻（笔画覆盖率低约一成），图注墨色 `.84 → .90`，观感落在原来那个"轻"上。

## 第九轮 · 悬停折角跑到书沟上（2026-09-18 下午）

用户反馈（附截图）：**「图书翻页有问题吧，怎么会在那个位置上出现呢」** ——
图里书页**中缝（书沟）**上翘起了一角，那里不该有折角。

### 根因

`drawFold` 的锚点：`const px = right ? this.spineX + pw : this.spineX;`
**左页那半边少了一个 `- pw`。**

关键在 `spineX` 的语义**随模式漂移**：合书时 = 当前页左边；**跨页时 = 书沟**
（左页在 `spineX - pw`，右页在 `spineX`）。左页折角要的是左页**书口边**（外侧），
写成 `spineX` 就正好落到书沟上。右页那半边本来就是 `+pw` → 一直是对的
→ 症状表现为"只有左页会错"，看着像随机故障。

### 修法

`right ? this.spineX + pw : this.spineX - pw`，两侧都显式取各自的书口边。

### 取证方法（这条值得记）

- "找浅色三角"量不到（那片是渐变，阈值挑不出边界）。改成
  **同一帧「开折角 / 关折角」两张图的像素差**，差的 bbox 就是折角真正落在哪：
  改前悬停左页 `x∈[463,515]`（书沟 463），改后 `x∈[95,150]`（左页书口边 99）。
- 复现"改前"不必找旧 HTML：从**已交付产物**里抽压缩后的函数体
  （大括号配对），把 `this.spineX-n` 还原成 `this.spineX`，页面里
  `eval` 出来覆盖 `BV.drawFold` 即可。见 `_shot_fold_before.mjs`。

### 踩到的坑

- **悬停目标 y 落到了画布外**：页面的逻辑下缘 `top+ph=545` 而 canvas 元素高只有 535
  （被裁掉 10px）。照 `top+ph-6` 去点 → 点到画布外 → 折角压根不触发，
  两张截图看着像"悬停没生效"。改成 `min(top+ph, 元素高) - 14`。
  定案前读回 `BV.cornerOn` / `cornerSide` 确认真的触发了。
- 第一次截图对比时基线不稳（整页都在变）：原因是目标落在画布外，
  差别实际是"悬停画布 vs 没悬停画布"（页面会有整片微小抬升）。
  连拍三张基线确认稳定（diff=0）之后再看才算数。

### 验证

- **9 个套件 / 286 项全绿**：`test_landing` 13 → **15**
