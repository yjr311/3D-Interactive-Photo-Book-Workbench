## 第十轮：品牌改名「光匣 LUMEN」→「咔哒书 KADA」+ 图标/字标设计

**起因（用户原话）**：「logo需要改一下，名称为咔哒书，图标及logo你帮我设计一下，我看一下怎么样」
——「我看一下怎么样」意味着交付物必须**能看**，所以这轮不只出设计稿，也把改名**实测落地**进产物。

### 图标（48 网网格，最终稿）
方块圆角 + 挖空的一本摊开的书。SVG **单 path + `fill-rule="evenodd"`**：
外框子路径 + 书的两页子路径 → 书自然成为**透明洞**，自动适配深/浅底（深底上是深书、浅底上是白书），
一份矢量不用出两版。关键几何：外框 41.6×41.6 / 圆角 12.9（比值 0.31，接近系统级 App 图标圆度）；
书 31.0×20.3（占外框 74%）；中缝 2.1（两侧各 1.05，合上就是「一本书」）；页外缘外鼓 1.1；安全边 3.2。

最终 `d`（387 字符）：

a12.9 12.9 0 0 1 -12.9 -12.9 v-15.8 a12.9 12.9 0 0 1 12.9 -12.9 Z
M25.19 33.99C28.64 31.38 34.84 29.25 39.48 29.25C40.72 25.86 40.72 17.04 39.48 13.65

### 探索过程（5 轮、约 24 个候选，都渲染出来真看了）
- `<mask>` 挖洞**静默失败**（图形仍是实心）→ 改单 path + evenodd，一次成功。
- 「圆环 + 书」16px 下环与书糊在一起；「书 = 光圈」被读成**指南针**；
  「右页掀起」被读成**对话气泡**。→ 结论：越聪明的图形越容易读错，
  最后选了最朴素、16px 下仍站得住的那个。
- 自检用了 numpy 像素探针（不是眼睛）：断言「书是洞」= 中心像素应等于页面底色而非强调色。

### 改名：只改「用户看得见的」，其余一律不动
用 `BRAND` / `OLD_BRAND` 两个常量做**唯一真源**，默认值与迁移共用：
```js
const BRAND={name:'咔哒书', studio:'KADA STUDIO', spine:'KADA · 2026'};
const OLD_BRAND={name:'光匣', studio:'LUMEN STUDIO', spine:'LUMEN · 2026'};
```
**两件故意不动的事**：
1. 本机存档 key 仍是 **`lumen.prefs.v1`** —— 它不是用户可见文字，改了会让做过书的人丢掉存档。
2. 代码里的内部命名（`window.LUMEN`、CSS 变量、文件名）保留 —— 收益是零，代价是全部回归测试要跟着改。
   新增 `window.KADA = window.LUMEN` 别名。

**定向迁移**（`PERSIST.restore()`）：只把「原样等于旧默认值」的字段升级，用户自己改过的书名/署名/书脊不动。

### 踩坑（本轮唯一真 bug）
第一版迁移写成了 `s.opts.title / author / spine` —— 但这三个字段住在 **`s.book`** 上，不在 `opts`。
`DEFAULT_OPTS.author` 是 `undefined` → 迁移**把字段抹掉了**，而 `JSON.stringify` 会静默丢弃 `undefined`，
所以症状是**字段从 JSON 里消失**，不是值变错。回归 `B39` 一眼抓到：
`{"t":"{name}","bt":"咔哒书"}` —— `opts.title` 本该是 `{name}`，`book` 里三件套却全没了。
修正后补了 `B39c` 守 `opts.title` 必须保持 `{name}`。

## 第十一轮：图标返工 —— 改用「手绘质感」方向

**起因**：用户否掉上一版图标（"logo不是很好看呀"），并附了一张 **16×16 的手绘小鱼**当风格参考
（`clipboard-2026-09-20T03-46-28-051Z-5fed15de.png`），问"有没有类似这种的"。

### 关键动作：把参考图**逐像素量出来**，而不是凭感觉模仿
参考图是 16px 的小图，所以能直接反推出笔法参数。用 PIL 打印亮度矩阵量出：

| 参数 | 实测值 | 推论 |
|---|---|---|
| 描边宽度 | ≈1.2px / 16px = **7.5%** | 48 网格 → `stroke-width 3.4~3.6` |
| 描边亮度 | lum ≈ 60 | → **#4A2708** 深暖棕，**不是纯黑** |
| 填充亮度 | lum ≈ 176（#D8A890） | → **#EEC9A4→#D7A578**，不是奶油白 |
| 填/描亮度比 | ≈ **2.9** | 比值过大＝"卡通黑描边"；过小＝看不见轮廓 |
| 内部细节 | **2 条短线** | 信息量必须压到极低 |
| 倾斜 | ≈ 40° | 顶栏里要收到 13° |

**第一版栽在这里**：描边画了 5.4（11.3%，粗 50%）、填充用奶油白（lum 223，比值 7.4），
结果内部细节全糊成一坨黑。**先量化再画，比画完再调快得多。**

### 探索路径（每轮都渲染出来真看了）
1. 4 个候选（摊开书 / 合上书+搭扣 / 合上书+书签带 / 摊开书+火花）→ **搭扣被读成马克杯**，
   书签带是"方块带个钮"。**"合上的书"只有方轮廓，撑不起辨识度 —— 整条路废掉。**
2. 换「封面贴小照片」的相册 → 渲染出来是**洗衣机**。废。
3. 回到「摊开的小书」，把信息量压到最低（1 个实心块 + 2 条页线 + 1 条中缝）→ 成立。
4. 姿态对比（正放 / 倾 13° / 倾 20° / 带火花）→ **倾 20° 像要倒**，13° 最好。
5. **16px 专项微调**：中缝从 `1.9@.55` 改成 `2.6@.95`（实心），16px 下才读得出"一本摊开的书"，
   否则两个页尖像分开的翅膀。

### 尺寸：视觉分量要单独校
新图标比旧的琥珀方块**视觉分量轻**（书是宽而矮，方块是满格）。做法：`_scale.py` 把 48 网格路径
关于 (24,24) 按 **sx 1.055 / sy 1.17** 缩放（宽高不同比，变宽变厚），再下移 1.05 居中。
用 `<g transform="translate(...)">` 而不是手改 30 个数字 —— 手改必错。

### 交付物
- `咔哒书-LOGO方案2.html`：主推方案（真实顶栏 29px 实况）、三种姿态、**两种配色**
  （暖棕＝参考图色 / 琥珀＝跟产品主色）、尺寸尺（含 16px 判读用的 8× 真实像素放大）、
  单色版（currentColor）、与参考图的数值对照表、6 皮肤实况、favicon、与旧图标对照、落地清单。
- `咔哒书-图标对照.png`：现版 vs 新版（深/浅各一行）+ 尺寸尺，同一窗口尺寸。

### 两个新工具（可复用）
- `_mkprev.py`：**把候选图标换进真实产物的顶栏**再截图。做法是读出产物 HTML，
  正则替换 `<svg class="logo"…>…</svg>`，写临时副本（不碰产物）。这是判图标的唯一可靠办法 ——
  在自建预览页里看会失真（我就踩了：预览页漏了 `.brand` 外层，导致 `width:29px` 不生效，

### 意外发现：产物文件会在预览后被写回
收尾核对时发现产物从 1147626 变成 1150464 字节（mtime 也变了）。查下去：

## 第十二轮：修「发布尺寸没效果」

**用户反馈**：「这个导出的发布尺寸好像没有什么不同，具体的效果貌似并无什么效果」（附导出面板截图）。

### 先复现：不要相信设置，去解包文件
在页面里替换 `URL.createObjectURL` 拦下 ZIP 的 blob，再**页面内自己解包**：
扫 Local File Header → `DecompressionStream('deflate-raw')` 解压 → 读每张 JPEG 的 `SOF` 拿真实像素。

```
改成「方图」后直接导出：
  ZIP 文件名   咔哒书-成片-1080×1080-….zip
  README       画幅尺寸：方图 1080 × 1080
  实际 JPEG    960x1280     ← 上一批的旧画幅
```

**两条根因，缺一不可**：
1. `exportZip()` 只检查 `state.generated.length`（有没有成片），**从不检查它是否过期**；
2. 命名与 README 取**当前设置**而不是**画布实际尺寸**。

### 修法
- 新增 `ensureFreshArt()`：过期就**替用户点一遍「生成成片」**再打包（这不算旁路 —— 规则 10 允许
  "把面板上已有的动作替用户点一遍"）。`exportZip` / `exportCurrent` 都走它。
- **命名一律从画布读**，只在"预设像素 === 真实像素"时才显示预设名，否则「自定义 W × H」。
  这是第二道防线：即使守门哪天失效，文件名也不会说谎。
- 面板**在改尺寸的当下**就给可见反馈（"现有成片是 960 × 1280，和上面选的尺寸（1080 × 1080）不一致…"），
  过期原因列表补上「发布尺寸」，toast 从「点『按当前设置重新生成』出片」改成
  「导出时会先按新尺寸重出成片」——**行为改了，文案必须跟着改。**

### 为什么原来的测试没拦住（本轮最该记的一条）
`test_export` 的 E5/E8 断言的是 `spec.ratio === '3:4'`、`bookStale() === true`，即**"设置变了"**；
用户报的是**"文件没变"**。断言停在了"用户能看见的那一层"的**上一站**：设置 →（没人看的一站）→ 文件。
**前端那一站改了，末端完全可能没跟上。**

新断言直接跳到终点：解包读字节里的真实像素。四档预设逐档验"改完直接导出"，外加**反向对照** ——
把产物里的守门替换成 `if(false)return;` 另存一份（`_neg_pubsize.html`），同一操作必须发出 960×1280。
`test_export` 21 → **30 项**。

### 两次自己踩的坑（都在测试里，不在产品里）
- E22「前置」断言写死了 960×1280，但前面的用例把尺寸停在「故事全屏」了 → 前置本身不确定。
  改成在跑之前**显式把 spec 复位**。
- E27 断言提示里必须有 `960 × 1280`，但当时的"现有成片"是 1080 × 1440。
  改成**从画布读出实际值再比对**，不写死 —— 否则断言会随用例顺序飘。

### 顺手核实的（虚惊一场）
`core.js` 和 `app.js` 各自定义了一份 `generate()`。看着像重复定义的暗雷，
实际是 `build.py` 里有一条 core 补丁把 core 那份改名成 `generateLegacy` —— **故意的，不是 bug**。
（`ensureFreshArt` 里调的 `generate()` 因此解析到 app.js 那份，是对的。）

### 验证
- 产物 **1148788 字节 / 1.096 MB / 余量 106.9 KB**。
- **9 套件 / 299 项全绿**。
- 取证图：`咔哒书-发布尺寸-修复对照.png`（面板改前无提示 vs 改后有提示）。
- 文档：设计方案 §4.11 + §6.5（含"为什么原来没拦住"）；升级方案 §9.1.6。
- 新脚本：`_probe_zip.mjs`（解包取证）、`_shot_pubsize.mjs` + `pubsize_cmp.png`。

## 第十二轮 · 图标重做：手绘小书落地（用户："logo需要改，目前的logo还是旧版的"）

### 事情本身
第十轮把品牌改名 + 方块图标一起做完了；用户在方案页上看到方块图标后说
「logo不是很好看呀，有没有类似这种的」，附了一张 **16×16 的手绘小鱼**当**风格参考**。
方案做了两轮（`咔哒书-LOGO方案.html` 讲方块那版、`咔哒书-LOGO方案2.html` 讲手绘那版），
用户没回答"选哪个姿态/配色"，直接说"logo需要改，目前的logo还是旧版的" —— 按推荐项落地。

### 关键判断
- **参考图给的是参数，不是感觉**：16px 逐像素打亮度矩阵 → 笔宽 7.5%、描边/填充亮度 60/176、
  比值 2.9、内细节 2 条。第一版凭感觉画成 11.2% / 223 → 粗 50%、亮 47 点，"看着不对劲"是算术问题。
- **图标不跟强调色走**：被换掉那版 `fill="currentColor"`，换皮肤/切浅色主题就变色。
  品牌色 = 当前皮肤色就不成其为品牌色。定稿固定暖棕（`#eec9a4→#d7a578` + `#4a2708`）。
- **视觉分量要补回来**：48 网格绕 `(24,24)` 缩放 `sx 1.055 / sy 1.17`（对齐旧方块 41.6 外框）
  → `translate(0 1.05)` 居中 → `rotate(-13 24 24)`。实测新旧图标在顶栏的盒子都是
  `l:42 t:36 87×87`（zoom 3 → 29×29 CSS），所以对照图可以硬裁同一个矩形。

### 改了什么
- `src/head.html`（`_patch_logo.py`）：favicon → 同源矢量 data-URI（len 2194）；顶栏 `<svg class="logo">`
  换几何（含 clipPath 那层"铅笔双描边"）；删掉 `.brand .logo{color:var(--accent)}`；
  投影 `0 5px 15px var(--glow)` → `0 2px 5px rgba(0,0,0,.34)`。
- 产物 1148788 → **1151411 字节（1.098 MB，余量 104.4 KB）**。
- 产物值级校验：新路径 `M4.69 12.42` ×3、旧方块 `M16.1 3.2` ×0、`#4a2708` ×4、
  渐变两端各 ×1、`rotate(-13 24 24)` ×1、`data-page-node-id` **×0**（干净）。
- `test_book.mjs` 44 → **51 项**（B40–B46：尺寸/几何/渐变端点/**栅格化数像素含反向对照**/favicon 同源 + 16px 栅格化）。

### 踩的坑

  报 "cannot stat"，而 Python `os.listdir` 看得见。文件操作一律改走 Python。
- `_close_logo.py` 的归档断言写错判据：拿"方块图标的 path 字面量"去认那份旧方案页，
  而那份是用 `<rect>` + JS 常量画的，页面里根本没有 inline path → 断言必挂。
  改成认**小节标题**这种结构性标记。
- **项数口径一直有误**：`test_landing` 实测是 **12**（②那条在 3 个翻页场景上各跑一次），
  文档一直写 15 → 第十/十一轮的合计（290/299）各虚高 3，真值 **287 / 296**。
  已在本轮文档里校正，并写进 MEMORY：**项数以套件打印的 PASS 行为准**。
- 拼图脚本末排文字被画到画布外（少留 30px）—— 第一版看着像被截断。

## 第十三轮：第二批「能玩」落地（贴纸 · 音效 · 九宫格 · 日期戳/票根 · 双封面寄语）

**用户原话**：「ok继续完善方案里的第二批内容」—— 指 §9 节奏表里
`贴纸与手写涂鸦 · 氛围音效 · 九宫格小卡页 · 日期戳/票根 · 双封面寄语`。

### 为什么五项一起做
它们共用同一块地基 —— **一件贴纸的数据模型**。其余四项都是它的邻居：
九宫格是一种**版式**、音效是一种**交互反馈**、双封面寄语是两处**文字位**，
而日期戳与票根本来就是贴纸里的两枚。先把贴纸立住，其余三项各接一根线就完事。

### 贴纸（8 枚）
- 和纸胶带 / 小星星 / 小爱心 / 闪光 / **手写圈** / **日期戳** / **纪念日戳** / **票根**。
  每枚一只对象 `{k,x,y,rot,s,text}`，`x/y` 是**相对照片**的 0..1，一枚一只、一册最多 6 枚。
- **坐标归一化是整块的根**：一份数据同时喂缩略图 / 胶片 / 成片 / 书页 / 分享长图，换画幅不用换算表。
- **烧进成片**（`renderCanvas` + `renderPlain`，都在 `finalize` 之前调 `drawStickers`）。
  书页画面有 `art='tpl'|'plain'` 两态、封面还会再挑一张照片 ——
  贴纸若只画在书页上，用户一切"干净照片"就凭空消失。烧进成片后这三处**零额外代码**。
- **新鲜度必须看得见贴纸**：`generate()` 存 `stick:stickerSig(p)`，`bookStale()` 拿它比；
  否则贴完贴纸书页一直是旧的（又一个"改了却看不见"）。
- 手写涂鸦**不是自由画笔**（按 §10 建议①仍不做），形态是"选一个圈 + 写一句话"。

### 九宫格：刻意不进"一键推荐"
第 5 种版式 `grid`：3×3 白卡（投影 + 细边）+ cover 填充的小图 + **每格保留自己的小图注**；
配套 `perPage(layout)`（two→2 / grid→9 / 其余 1），`buildBookPages()` 与面板"第 N 张"走它。
**不进任何 `SKINS[*].rec.layout/alts`** —— 一键成书是给"不想做决定的人"用的，
而 28 张铺成九宫格联系表不是相册。守它的两条断言要一起写：
**0 套皮肤推荐它** ∩ **它确实在 `LAYOUTS` 里**（只写前一条，把 `grid` 删掉也能"通过"）。

### 双封面寄语 / 氛围音效
- `book.coverNote`（封面书名下、署名上，沿**封面内容轴**居中 —— 封面有书脊，内容轴不是 `W/2`）/
  `book.backNote`（`END OF VOLUME` 细线与条形码之间，`W*.0234`，`wrapText(...,3,...)` 最多 3 行、超了省略号）。
  默认都是**空串** → 老存档像素级不变，**这一项不需要写迁移**；空时那一段一个像素都不画。
  新增 `wrapText()` 放在 `trackedW` 旁：CJK 逐字断行、量宽走 `trackedW`（直接量 `measureText` 会少算字距）。
- `Sound` 重写：`swish / land / pop / isOn / setOn / toggle`，公共 `noise()` + `blip()`，
  **纯 WebAudio 程序生成、零素材零请求**。每个函数体 try/catch —— **音频是装饰，绝不许打断交互**；
  `state.sound` 进存档；**顶栏与面板两处开关一个状态**（顶栏按下要同步面板里的勾）。

### 四个坑（全是"静默失败"那一类）
| 坑 | 症状 | 根因 |
|---|---|---|
| `stkAnniv` 里 `const R=S*.70` | 一画纪念日戳就崩，而面板那格**只是一片空白** | 撞了 core.js:5 的全局 `const R=n=>Math.round` → `R(size)` 变成"调用一个数字"。**面板每格都包在 try/catch 里**，所以崩在没人看得见的地方 |
| `R(i/3)` 当九宫格行索引 | 9 格铺成 2/3/3/1、第 9 格跑到版心外 | `R` 是**四舍五入**不是取整：i=2→行1、i=8→行3。改 `Math.floor` |
| 和纸胶带小样一片空白 | 面板第一格什么都没有 | 它是**纸色半透明**，而小样底色用的就是纸色 —— 同色叠同色。给 `stkPalette()` 补 `chip:'#b9b2a6'` 当"看样台面" |
| `s.text` 把 `''` 与 `null` 混成一个 | 用户删光日期戳的字，松手又跳回默认值 | `s.text==null\|\|s.text===''` 都回退。改成只有 `null`（从没设过）才回退，加贴纸时就把 `dflt` **显式写进数据** |

⚠ 上面第 3 条**补完之后第一版断言变成假绿**：它数的是 `alpha>8` 的像素，把底色一起算进去了；
改成数"与 chip 色不同的像素"。第 4 条**修完 `stkText` 后 `drawSticker` 里同款第二份**（`s.text||def.dflt`）
立刻被测试抓出来 —— 同一语义只看一处是不够的。

### 取证方法（比结论值钱）
- **贴纸几何必须在"填白的画布"上量。** 样例照片是深色抽象渐变，"深色像素 bbox"**恒等于整张画布** ——
  "涂鸦变宽了"和"什么都没变"量出来一模一样，两个相反结论都能"通过"。
  改白底之后**顺带把上面那个 `R` 崩溃逼了出来**（崩在 try/catch 外面了）。
- **画布里有 `Math.random`（封底条形码是全篇唯一一处）时，位置量测 = "两次渲染求差" + "只取第一段连续差异行"**
  （允许中间空 `H*.03`）。否则随机条码把差异带一路拖到页脚，"一句话"的 bbox 变成整整一页。
  间隙一开始写 6px → 把三行寄语砍成第一行，报出**假失败**"18px→19px"；
  真实行距约 13px、到条形码有 130+ 行，3% 分得干净。
- **反向对照**：清空贴纸后画面必须**逐像素**回到原样；同一枚贴纸在 5 种画幅上落在同一归一化点
  （实测 x = 0.740 / 0.739 / 0.740 / 0.739 / 0.738，短边占比同为 18.1%）；
  封面寄语为空时与"确定性重渲染"的差异必须 **0 像素**。
- `renderPlain` 单独验不出书页上的贴纸 —— 页面的 canvas 是 generate 时就烤好的，
  断言必须走"贴 → 重出 → 书页"整条链，`art` 两态各一遍。
- 两条小口径，本轮都真实误报过：**滑杆容差 = 控件自己的 step**（`range` 吸附到 0.01，
  用 1e-6 比会报"滑杆 0.7 / 数据 0.7006"）；**"改动之后再读的值"不是那次改动后的值** ——
  加贴纸到上限的循环跑完才读数量 → "0 → 6 枚"（应在首次点击后立刻取）；
  假定 `b.goto()` 重载后仍在第 2 步（实际回第 1 步）→ 拿到 `null`。

### 面板 / 交互的三个决定
- **加贴纸有 6 个固定落点、没有随机** —— 测试与截图才可复现（同 §12 的确定性原则）。
- **指针事件挂 document 而不是 canvas**：`renderPanel()` 每次都会重建那块 canvas，
  挂在元素上的监听器会随元素一起消失。拖动中**不写存档**，松手才 `PERSIST.save()`。
- `input` 事件里**绝不重渲面板**（焦点丢失），只刷读数 + 重画 + `schedulePreview()`。
- 面板另给一块**照片比例的画布**当预览：贴纸坐标是照片相对的，它在页面里出现在哪还取决于版式，
  没有它用户就是**盲贴**。用照片自己的长宽比 → canvas 坐标 ↔ 贴纸坐标 **1:1**，不需要换算表。
- `plateHasText`（同一信息不出现两次）**刻意不套用在贴纸上** —— 贴纸是用户亲手贴的，
  他觉得重复也是他要的；把"用户明确放的东西"也抑制，就又回到"改了却看不见"。

## 第十四轮：贴纸「改了看不见 + 位置对不上」（用户反馈补做）

用户原话：「我修改不是动态呈现的，添加甚至修改后，需要手动点击生成照片才有，
这不太好，甚至是删除贴纸也是这样的」+「这个贴纸修改的位置，在已有的照片显示那不同模版显示，
会导致贴纸修改的位置对不上，这咋整，**预览里也要是带有模版的照片**？你看看吧怎么弄最合理最好看最好用」

### 一句话根因
贴纸坐标的**含义**是"归一化到照片"，但落到像素时乘的是**画布**尺寸（`cx = s.x*W`）。
"照片在画布里占哪一块"只有渲染那一刻才知道 → 三种模版的照片矩形实测 `magazine 0,0,960,1280`
/ `polaroid 72,-3,816,1088` / `film 96,128,768,1024` 互不相同 ⇒ 同一个 `x=0.5` 落在三处。
**两条抱怨是同一行代码**，所以一起修。

### 改了什么（六处）
1. `drawFit()`/`paintPhoto()` 返回照片矩形 → `renderCanvas`/`renderPlain` 挂 `c.photoRect`；
   锚点 `dx + x*dw`，基准尺寸 `min(dw,dh)*0.20`。
2. `drawSticker(x, rect, s, i, im)` **只收矩形**（刻意删掉了 `(W,H)` 数字兼容重载）。
3. 面板画布改成 `drawImage(g.art)` —— **就是那张成片（含模版）**，加一道双描虚线标照片边界。
4. 底片按 `stkBaseSig(p)` 缓存，拖动时只 `drawImage(底片)+drawStickers(实时)`。
5. `refreshStickerArt(p)` 只重出**这一张** + `scheduleArt(p)` 120ms 去抖 → `scheduleBook`/`schedulePreview`
   + `renderDock` + `PERSIST.save`；**六个改动点全改走这条路**。
6. 指针换算从一步变两步（`÷显示尺寸×画布px` 再 `−矩形原点÷矩形尺寸`）。

### 不调 generate() 的原因
它会重建 `state.generated`、重置 `_genSig`，第 1 步还可能把用户切走 —— 是副作用不是刷新。
实测成本：`refreshStickerArt` 29ms / `buildBookPages`(34页) 89ms / `BV.setPages` 41ms；
里程碑 **成片 170~201ms、书页 326~369ms**。

### 最值钱的三个发现
- **检测器造出了"产品很慢"**：第一版延迟检测器每 30ms 调一次 `buildBookPages()`
  （每次新建约 40 张 880×1173 画布）→ 主线程被拖住，量到 **1412ms**，
  而页面内里程碑只有 170/369ms（**差 2~5 倍**）。改用 `BV.pages`（屏上真在显示的画布）后正常。
  ⚠ `BV.pages` 存的是**画布**、`BV.kinds` 存类型，画布没带页码 → 只能"找第一个内容页"。
- **定时器节流假说被自己的数据否掉**：怀疑后台标签页钳 1s（`hasFocus()` 确实 false），
  实测 `setTimeout(30/40/120)` = **31/41/121ms**，`visibilityState` 是 visible。
  同一轮里 `setInterval(1)` 采样器自己被饿死（报 933ms 空档，其间有任务在跑）—— **采样器也会说谎**。
- **心形的墨天生比锚点低 `0.086·S`**（8 枚全量测过），所以"绝对居中"不是判定锚点的好标准；
  改成 ① 平移对照（挪 `(137,221)` → 墨迹挪 `(137,221)`）② 偏移按 S 归一化后跨矩形一致。
