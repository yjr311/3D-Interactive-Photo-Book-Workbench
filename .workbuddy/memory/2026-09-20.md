## 第十轮：品牌改名「光匣 LUMEN」→「咔哒书 KADA」+ 图标/字标设计

**起因（用户原话）**：「logo需要改一下，名称为咔哒书，图标及logo你帮我设计一下，我看一下怎么样」
——「我看一下怎么样」意味着交付物必须**能看**，所以这轮不只出设计稿，也把改名**实测落地**进产物。

### 图标（48 网网格，最终稿）
方块圆角 + 挖空的一本摊开的书。SVG **单 path + `fill-rule="evenodd"`**：
外框子路径 + 书的两页子路径 → 书自然成为**透明洞**，自动适配深/浅底（深底上是深书、浅底上是白书），
一份矢量不用出两版。关键几何：外框 41.6×41.6 / 圆角 12.9（比值 0.31，接近系统级 App 图标圆度）；
书 31.0×20.3（占外框 74%）；中缝 2.1（两侧各 1.05，合上就是「一本书」）；页外缘外鼓 1.1；安全边 3.2。

### 探索过程（5 轮、约 24 个候选，都渲染出来真看了）
- `<mask>` 挖洞**静默失败**（图形仍是实心）→ 改单 path + evenodd，一次成功。
- 「圆环 + 书」16px 下环与书糊在一起；「书 = 光圈」被读成**指南针**；
  「右页掀起」被读成**对话气泡**。→ 结论：越聪明的图形越容易读错，
  最后选了最朴素、16px 下仍站得住的那个。
- 自检用了 numpy 像素探针（不是眼睛）：断言「书是洞」= 中心像素应等于页面底色而非强调色。

### 改名：只改「用户看得见的」，其余一律不动
用 `BRAND` / `OLD_BRAND` 两个常量做**唯一真源**，默认值与迁移共用：
```js
const BRAND={name:'咔哒书', studio:'KADA STUDIO', spine:'KADA · 2026'};
const OLD_BRAND={name:'光匣', studio:'LUMEN STUDIO', spine:'LUMEN · 2026'};
```
**两件故意不动的事**：
1. 本机存档 key 仍是 **`lumen.prefs.v1`** —— 它不是用户可见文字，改了会让做过书的人丢掉存档。
2. 代码里的内部命名（`window.LUMEN`、CSS 变量、文件名）保留 —— 收益是零，代价是全部回归测试要跟着改。
   新增 `window.KADA = window.LUMEN` 别名。

**定向迁移**（`PERSIST.restore()`）：只把「原样等于旧默认值」的字段升级，用户自己改过的书名/署名/书脊不动。

### 踩坑（本轮唯一真 bug）
第一版迁移写成了 `s.opts.title / author / spine` —— 但这三个字段住在 **`s.book`** 上，不在 `opts`。
`DEFAULT_OPTS.author` 是 `undefined` → 迁移**把字段抹掉了**，而 `JSON.stringify` 会静默丢弃 `undefined`，
所以症状是**字段从 JSON 里消失**，不是值变错。回归 `B39` 一眼抓到：
`{"t":"{name}","bt":"咔哒书"}` —— `opts.title` 本该是 `{name}`，`book` 里三件套却全没了。
修正后补了 `B39c` 守 `opts.title` 必须保持 `{name}`。

## 第十一轮：图标返工 —— 改用「手绘质感」方向

**起因**：用户否掉上一版图标（"logo不是很好看呀"），并附了一张 **16×16 的手绘小鱼**当风格参考
（`clipboard-2026-09-20T03-46-28-051Z-5fed15de.png`），问"有没有类似这种的"。

### 关键动作：把参考图**逐像素量出来**，而不是凭感觉模仿
参考图是 16px 的小图，所以能直接反推出笔法参数。用 PIL 打印亮度矩阵量出：

| 参数 | 实测值 | 推论 |
|---|---|---|
| 描边宽度 | ≈1.2px / 16px = **7.5%** | 48 网格 → `stroke-width 3.4~3.6` |
| 描边亮度 | lum ≈ 60 | → **#4A2708** 深暖棕，**不是纯黑** |
| 填充亮度 | lum ≈ 176（#D8A890） | → **#EEC9A4→#D7A578**，不是奶油白 |
| 填/描亮度比 | ≈ **2.9** | 比值过大＝"卡通黑描边"；过小＝看不见轮廓 |
| 内部细节 | **2 条短线** | 信息量必须压到极低 |
| 倾斜 | ≈ 40° | 顶栏里要收到 13° |

**第一版栽在这里**：描边画了 5.4（11.3%，粗 50%）、填充用奶油白（lum 223，比值 7.4），
结果内部细节全糊成一坨黑。**先量化再画，比画完再调快得多。**

### 探索路径（每轮都渲染出来真看了）
1. 4 个候选（摊开书 / 合上书+搭扣 / 合上书+书签带 / 摊开书+火花）→ **搭扣被读成马克杯**，
   书签带是"方块带个钮"。**"合上的书"只有方轮廓，撑不起辨识度 —— 整条路废掉。**
2. 换「封面贴小照片」的相册 → 渲染出来是**洗衣机**。废。
3. 回到「摊开的小书」，把信息量压到最低（1 个实心块 + 2 条页线 + 1 条中缝）→ 成立。
4. 姿态对比（正放 / 倾 13° / 倾 20° / 带火花）→ **倾 20° 像要倒**，13° 最好。
5. **16px 专项微调**：中缝从 `1.9@.55` 改成 `2.6@.95`（实心），16px 下才读得出"一本摊开的书"，
   否则两个页尖像分开的翅膀。

### 尺寸：视觉分量要单独校
新图标比旧的琥珀方块**视觉分量轻**（书是宽而矮，方块是满格）。做法：`_scale.py` 把 48 网格路径
关于 (24,24) 按 **sx 1.055 / sy 1.17** 缩放（宽高不同比，变宽变厚），再下移 1.05 居中。
用 `<g transform="translate(...)">` 而不是手改 30 个数字 —— 手改必错。

### 意外发现：产物文件会在预览后被写回
收尾核对时发现产物从 1147626 变成 1150464 字节（mtime 也变了）。查下去：
文件里多了 **66 个 `data-page-node-id="…"` 属性**，正好 +2838 字节。
是 **WorkBuddy 预览面板**给每个元素插的（点选元素用），而且是**写回磁盘**的 ——
归档的旧产物 `_prev_光匣-3D互动照片书.html` 里也有 64 处，说明一直如此，只是以前没注意。

- 恢复方式：重跑 `build.py`。已重跑，产物回到 **1147626 字节 / 1.094 MB / 余量 108.1 KB**，
  `data-page-node-id` 0 处。
- **口径修正**：体积预算只能看 `build.py` 打印的数（它量的是刚拼出来的字符串），
  不能 `ls` 磁盘文件。已写进 MEMORY 规则 30。
- 功能无影响（纯属性），但**不能拿磁盘文件做字节级 diff / 哈希比对**。
