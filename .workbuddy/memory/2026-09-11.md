# 2026-09-11

## 光匣 LUMEN · 3D 互动照片书工作台

**交付**：`光匣-3D互动照片书.html`（单文件、零依赖、可离线）、`光匣-设计方案.md`、4 张预览图。

**产品结构**：三层管线共享同一份 `state` —— 素材层（导入/规格/调色）→ 模版层（11 套 Canvas 模版）
→ 成书层（3D 选片条 + 翻页引擎 + 导出）。

**关键技术决策**
- 不引入 turn.js / StPageFlip，自研 CSS 3D 翻页引擎。理由：离线可用、与 Canvas 渲染管线共状态、
  页面内容自由度不受限。
- 翻页采用真实纸张模型：sheet 绝对定位于右半边 + `transform-origin:left center`（装订线）+
  正反面 `backface-visibility:hidden` + **z-index 精确排序**（未翻 `n-i`，已翻 `i+1`）。
- 拖动角度 = `180° × (指针位移 / 2×页宽)`，越过 −90° 提交。
- 书盒 `translateX(-25%)` 让封面居中，且随拖动进度 `-25%×(1-t)` 连续插值。

**踩过的坑（重要）**
1. `const FB = new (function(){ return function(){ this.bind(); }; })()` —— 匿名构造函数的 prototype
   与 `FB.prototype` 不是同一个对象，构造时 `this.bind` 为 undefined。必须写成具名 `function FlipBook(){}`
   + 原型方法挂载完成后再 `const FB = new FlipBook()`。
2. `generate()` 里生成的对象漏了 `picked:true`，导致书本初始为空。
3. `prep()` 旋转逻辑写反：`r%180===0` 时才应保持原尺寸，90/270 才交换宽高。
4. `book.num` 被放进 NUMKEYS，导致 `parseFloat(true) === NaN`。
5. 奇数页数需在**封底之前**补空白页，才能保证封底落在纸张背面。

**验证方法（可复用）**
- 无头 Chromium 路径：`C:/Users/zz/AppData/Local/ms-playwright/chromium-1228/chrome-win64/chrome.exe`
  （无需安装 playwright 包，直接用已缓存的 chrome.exe）。
- **注入式自检**：把待测 HTML 复制一份，在 `</body>` 前注入一段脚本，把断言结果写入
  `<div id="__test" data-xxx="...">`，然后 `chrome --headless --virtual-time-budget=20000 --dump-dom`，
  再用 node 正则解析 `data-*`。这比截图可靠得多。
- 校验 3D 变换是否真正生效，要用 `getComputedStyle(el).transform` 读 `matrix3d`，
  以及 `getBoundingClientRect().width` 的投影压缩，**不要依赖截图** ——
  headless 软件合成下，变换过的图层在截图里可能仍是旧帧。
- `--screenshot` 必须传**转义后的绝对路径**（`--screenshot=C:\\...\\x.png`），
  相对路径会被写到 Chrome 自己的 cwd；且旧版 `--headless` 能出图，`--headless=new` 不出。
- 手写 ZIP（store + CRC32）用 Python `zipfile` 校验：`z.testzip()` 返回 None 即通过。
