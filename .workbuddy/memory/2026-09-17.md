### 结论：CSS 3D 翻页（v1 方案）根本做不出好看的纸张，改为 canvas 自研物理翻页
排除了四版模型后定稿为 **「剥离式卷曲」（peeling curl）**：
- 切线角剖面 `A(t)=π·A1·[(1-λ)+λ·(t/tc)^0.7]`，自由边领先、书脊滞后；`tc` 是落页点，随进度 1→0
  内移，保证 q=1 时全页 A=π 平整落在左页（不会悬空、不会对折）。
- 沿纸面积分 `X=∫cosA du`、`h=∫sinA du`，`h` 再以落页点为基准归零（`h -= h(tc)·smoothstep(t/tc)`）。
- 屏幕投影：`sx = spineX + m·X`，`sy = cy ± H/2 - h·KZ`（KZ 随 q 递减），于是纸真的“立起来”
  并且上/下边缘是曲线。
- 渲染顺序：投影 → 剪影底色+clip → 逐条带 drawImage → 分段线性渐变着色（在折返点 kr 分段，
  保证 x 单调，避免瓦楞纹）→ 纸边高光。
- 着色由可见面法线点乘光源得出：`nl = .4205·sinA + .841·|cosA|`，`d=.90·(1-nl)^1.30`。

**关键踩坑**
1. **“整页绕书脊刚性旋转”是错的**：q=0.5 时全页侧立，投影塌成一条黑边。
2. **“行进式 180° 滚卷”也是错的**：卷曲带吃掉 30% 弧长，剩余部分会**对折盖回本页**，
   屏幕上出现一条半透明灰带（很像 UI bug）。
3. **抬升高度不能直接取 ∫sinA**：高度单调递增会让后半程整张纸悬空飘着。
   必须以落页点为地面基准做归零。
4. 侧立处（|cosA|→0）内容会被极限压缩成糊状半透明带 → 用 `globalAlpha` 让图文随 facing 淡出。
5. **图层接缝**：`flatPage` 里画的书脊渐变与 `drawSheet` 的纸面副本不同步，会露出硬边；
   改成把书脊阴影统一挪到 `drawSheet` **之后**画。
6. **底部胶片带“被遮挡”**：真实原因是 `@media(max-height:680px)` 把 `.app` 改成 `height:auto`
   + `body{overflow:auto}`，`.work{min-height:400px}` 把 dock 顶出视口。改为短窗口也保持
   `height:100dvh` 且 `--dockH:clamp(118px,16.5vh,152px)`。
   另外 `.dock-inner{position:absolute;inset:0}` + `--dockH:clamp()` + `.sitem` 由 `--dockH` 计算，
   保证 9 种窗口尺寸（1920x1080 → 900x700）都不溢出、不裁切。

## 追加（同日）：修「点击模版切换无反应」+ 两处连带问题

### 根因（已用真实鼠标事件复现确认）
`#tplbar` / `#strip` 的 `pointerdown` 里直接 `setPointerCapture(pointerId)`，
浏览器会把这次按压产生的 **`click` 事件整体重定向到捕获元素**：
`e.target` 变成容器本身，`closest('.tplcard')` / `closest('.sitem')` 恒为 `null` → 早退。
连卡片/照片自己挂的 `click` 监听器也完全不触发。
之前自检用的是 `el.dispatchEvent(new MouseEvent('click'))`（合成事件，绕开捕获），
所以一直「通过」——**这是本轮最该记住的教训：点击类问题必须用真实输入事件验证。**

最小复现：`tmp/repro_capture.mjs`（真实点击，输出 `click target=bar closest=NULL`）。

### 修复
1. **捕获推迟到真拖动之后**：`pointerdown` 只记起点不捕获；`pointermove` 里位移 >4px
   （x/y 任一轴）才 `setPointerCapture`。普通点击不再被抢走 click。
2. **兜底命中**：`click` 处理器里 `closest()` 落空时，用
   `document.elementFromPoint(e.clientX, e.clientY)` 再试一次。
3. **抑制窗口改用时间戳**：原来的 `TPLBAR.moved` 標志位 + 点击时复位，
   在「拖到容器外松手（不发 click）」时会残留 true 并吞掉下一次真点击。
   改成 `TPLBAR.sup / STRIP.sup = performance.now() + 70`。
4. **`window` 级 `pointerup` 兜底**：拖出容器外松手也能收尾，不留 grabbing 状态。

`translateZ(-|d|*74)` 被推到它**后面** → 平面挡住命中测试，`elementFromPoint()` 命中的是
`strip-track` 而不是照片。**除居中那张外，两侧照片一律点不中**（「点两侧照片居中」实际是坏的）。
修：`.strip-track{pointer-events:none}` + `.sitem{pointer-events:auto}`。

## 第二轮：用户反馈的三个视觉问题（已修复 + 验证 + 出图）

用户原话：「图书左边还是有痕迹阴影啊，还有每次翻页落地后会白一下怎么回事，
还有这中间的大黑点是什么，能不能取消掉」。三处全部定位到具体代码行，用像素取证修复。

### ① 合着书时书脊左侧桌面有灰痕
`draw()` 里书脊阴影是 `createLinearGradient(spineX-SW, 0, spineX+SW, 0)`，SW=58，
**无条件铺 ±58px**。合着书（`cur=0`，左侧没有纸）时左半条渐变仍画在桌面上 → 灰痕。
修：渐变跨度按实际纸面裁（`x0 = spineX - SW*lIn`，`x1 = hasR ? spineX+SW : spineX`），
`put()` 丢掉越界 color stop 后按比例重映射（保证峰值仍在书脊上，不会整体变淡）。

### ② 每次翻页落地会白一下

中段保留着色、两端收敛到 0。**踩过的坑**：先试减常数 `D_FLAT≈0.0824` 归一化 ——
把中段压成 0（纸面着色整段消失），而且公式在 A≈0.4 有个非单调小鼓包。
高光改成 `globalAlpha = .55*clamp(liftN*1.5,0,1)`。

## 第三轮：翻页中段「图没了」+ 封面未开左侧有痕迹

用户截图（1920×919，浅色主题）反馈两条：① 翻到中间那一帧纸上的照片**直接没了**，只剩空白纸；
② 封面还没翻开，书**左边**桌面上就有一道渐变痕迹。

### ① 中段「图没了」= 四因叠加（主因是条带采样比例错）

**主因 a —— `drawSheet` ③ 内容条带固定像素外扩**
原来写死 `ov = .6; grow = (ov / max(.30, |w|)) * sw`。纸转到近 90° 时最窄条带目标宽
`|w| ≈ 0.5px`，于是 `grow ≈ 1.2·sw`，**源切片被撑到 34px 塞进 1px 目标** →
浏览器对整页做极限降采样，平均出来就是纸色，看起来「图没了」。
`probe_log.py` 取证：修前 `src[6+33] -> dst[680+1]`；修后 `src[646+11] -> dst[679+0.5]`，
比值正好回到几何压缩比 ~13。
**修法**：外扩量按条宽**成比例**，不再固定像素 ——
`ov = min(.55, aw*.34); grow = (ov/aw)*sw;` 每侧 `srcA -= grow`、`srcW = sw + 2*grow`。
这样采样密度恒等于几何压缩比，任何条宽下都不会过采样到糊。

**加剧 b —— 90° 侧立停留太久**
`q` 是线性的，纸在 q≈0.5 附近以 `cosA→0` 的速度塌缩，跨度只剩页宽 1/6 却停留约 1/5 时长。
**修法**：相位重映射 `qw(x)`，两端严格不动、中间变陡（指数 0.55）：
`u = x*2-1; qw = .5 + .5*sign(u)*|u|^0.55`。最窄跨度 55px(q=.55) → 88px(q=.50)，
且 `q=0/1 ↔ 0/1` 端点不动 → 不影响落地连续性。

**加剧 c —— 书脊侧中段折回糊成一坨**
`lam`（书脊侧滞后量）原来 `.86*(1-q²)`，中段书脊侧还剩 0.65 的滞后 → 那一侧折回去对折。
**修法**：`.94*(1-qw^6.0)`，q=0.5 时滞后降到 0.075。`|cosA|<0.25` 的不可读条带占比
56% → 40%，投影跨度 88 → 141px。

**加剧 d —— 侧立段被当成纸面压暗**
`darkOf` 按可见面法线点乘光源，侧立时 `|cosA|→0` 会让内容整体压成灰糊。
**修法**：按投影跨度算 `spanN = clamp((spanMax-spanMin)/(W*.34),0,1)`，
`faceLight = .30 + .70*spanN` 乘进着色（越侧立越不压暗），
`pr = pow(sin(π*qw), .9) * liftN`。收敛后侧立段读成**亮边在翻**，不再是灰糊。

### ② 封面未开左侧痕迹 = 书脊阴影须「两侧都有纸」才画

`draw()` 里书脊阴影原来只看「左侧有没有下层纸」`hasStaticL`。合着书（`cur=0`）时左侧
本来就没有纸，但翻页起手瞬间 `moving.dir==='back'` 的早退分支会让 `lIn` 提前长出来 → 左痕迹。
**修法**：引入书沟存在度 `gut = min(lIn, hasR?1:0)` —— **缺任一侧就恒为 0**，
连宽度也一起收：`SWg = SW*(.45+.55*gut)`，`gut<=.02` 直接不画。
`cur=0` 时 `hasStaticL=false → lIn=0 → gut=0`；跨页态 `lIn=1, hasR=1 → gut=1`，与原来一致。

> 取证注：当前构建在封面态**画布 alpha 已经是 0**（`probe_cover.py` 读到 `0,0,0,0`，
> `cmp_light.py` `desk0_70 alpha.max=5`）。用户那张截图与我们的渲染在 x=710–790 处
> 差一个 `151→223` 的暗渐变（我们是平纸 `229,227,218`），**判断截图来自修复前的版本**。
> 但逻辑仍按「两侧存在」强化，并加了硬断言防回归。

## 第四轮：流程返工 —— 每张照片独立模版 + 先选片再生成 + 首屏不自动载入示例

用户原话：「我选择的模版到底知不知道被保存了的，比如我导入照片，为每张照片分配不同的模版，
然后再选择要生成图册的照片进行生成是吗，可现在的流程给我的感觉像个半成品，还有首先进去呢
先不加载示例照片，只有点击要加载示例按钮才显示」。

### 先说结论（这是产品设计缺陷，不是 bug）

1. **完全没有持久化** —— 全项目 `grep` 不到任何 `localStorage` / `indexedDB`。
   刷新即丢，所以用户"不知道有没有被保存"是准确的直觉。
2. **模版是全书唯一一套，不是每张一份**。`state.tpl` 是单个字符串，
   `renderCanvas(photo, state.tpl, ...)` 全局共用；照片对象里根本没有 `tpl` 字段。
   用户期待的"为每张照片分配不同模版"从来没被实现过。
3. **顺序是反的**：原流程是「生成成片 → 在成片上选片（步骤三的选片条）」，
   而用户要的是「先勾选入册 → 再生成」。而且步骤一/二根本没有勾选入口。
4. **首屏自动载入示例**：`app.js` 末尾 `setTimeout(()=>loadEmbedded(true),260)`。

### 改了什么

**A. 数据模型（core.js）**
- `makePhoto()` 新增 `tpl`（默认取当前 `state.tpl`）与 `picked:true`。
- `state.tpl` **语义改变**：从"全书模版"变成"胶片带当前高亮的那一套"＝当前选中照片的模版。
  新增 `syncTplFromSel()`：切换选中照片时把 `state.tpl` 同步成那张照片自己的模版，
  这样胶片带高亮永远跟着正在编辑的那张走 —— 用户能"看见"模版被记住了。
- `generate()`：`state.photos.filter(p=>p.picked)`，每张用 `p.tpl || state.tpl`。
  app.js 与 core.js 两处都改（core 的被 build.py 改名为 `generateLegacy`，是死代码，但保持同步防误读）。

**B. 持久化（core.js 新增 `PERSIST` 模块）**
- 先探测 `localStorage` 再使用；失败静默降级，并在面板「保存与记忆」里如实写
  「本机已开启 / 当前不可用」，另给「清除已保存的偏好与分配」按钮。
- 存 `{tpl, theme, spec, adj, preset, opts, book, assign}`。
- **`assign` 按照片名（自然键）存，不按 id**：`id` 每次运行自增，重新导入就对不上；
  示例照片名确定为 `LUMEN 01..28`，用户重导同名文件也一致，
  于是 `pushPhoto()` 里 `PERSIST.assignFor(p.name)` 能把模版与入册状态接回来（打 `_restored` 标记）。
- 写入去抖 200ms；在切模版 / 勾选 / 增删照片 / 改设置 / 切主题时调 `save()`。
- **照片本身不存**（几十 MB base64 塞不进 localStorage），UI 里明说这一点，不装作存了。

**C. 界面**
- 首屏移除自动载入；空状态改成「先从一张照片开始 + 完整流程说明 + 两个按钮」，
  按钮用事件委托绑定（内容是 innerHTML 动态注入的）。
- 素材栏新增 `.rail-tools`（`n / N 张入册` + 全选 / 全不选）；
  缩略图左上角新增常显的 `.pick` 勾选圈（有状态的信息不能只靠 hover），
  右下角新增 `.tplb` 模版徽章；未入册的缩略图降饱和变暗。
  **旋转按钮从左上角让位到右上角与删除竖排**（`left:auto;right:4px;top:27px`）。
- 顶部「生成成片」按钮直接写张数（`生成成片 · 14 张`），0 张时 `disabled`；
  用独立的 `genBusy` 标志防止渲染中被 `renderRail` 覆写回正常文案。
- 胶片带 `assignTpl(key, scope)`：`'sel'` 只改当前照片并 toast 说出改的是谁，
  `'all'` 铺给全部；两处入口（胶片带右侧 + 面板）都指向它。
- 面板：`panel0` 顶部加"已入册 n/N"；`panel1` 加"当前照片 / 它的模版 / 模版分配统计"；
  `panel2` 在"素材勾选数 ≠ 成片数"时提示并给「按当前勾选重新生成」。
- 没有素材时胶片带用 `demoPhoto()`（内置 `makeSample(1)` 缓存）渲染 11 套模版，不再是一排空框。

### 踩到的坑

**移除一个"自动执行"副作用，会静默打断所有依赖它的测试脚手架。**

所以没被补丁覆盖，跑起来才在 `b.center('.sitem[data-i="0"]')` 上崩掉（返回 null）。
→ 教训：改掉自动行为后，grep 的关键词要覆盖**所有**依赖方式（自动载入 / 自动生成 / 默认步骤），
不能只 grep 一个。

小坑：测试里写 `data-tpl="grid"` 不存在，真实键名是 `grid9`
（11 套：polaroid/film/magazine/kraft/neon/minimal/postcard/duotone/grid9/cinematic/titlecard）。
错误在测试不在产品，但差点误判成"应用到全部坏了"。

## 第五轮：翻页手感对标 StPageFlip + 「生成的初始图书太丑」

用户原话：「效果都很不错，图书翻页效果不太行，尤其是生成的初始图书模版也蛮丑的，你看看
https://haichaolihc.github.io/create-photo-flipbook-ui/ https://nodlik.github.io/StPageFlip/
效果实现一下」。

### 参考站抓不到，只能靠已知 API + 自身审美
写 `_ref.mjs`/`_ref2..4.mjs` 抓参考站，全部 `{"bookFound":false}` —— 书在 iframe 内、且在首屏
之下；同时 Read 工具读不了图（"model does not support images"），**没法目视参考站**。
→ 决定不再纠缠参考图，直接按 StPageFlip 的公开模型（软页用 canvas 卷曲、硬页用平面旋转 +
板厚度、`maxShadowOpacity`、`showCover`、`flippingTime`）+ 自己的物理直觉重做。

### ① 翻页：从「一种纸」升级成「两种材质」
- **普通内页**：λ 峰值 `.86→.34`（`lam = lamMax*(1-pow(qw,4.5))`）。之前 0.94 太"硬"，
  整页像一块板在转；0.34 才是纸 —— 书脊侧很快跟上、只有自由边在卷。
  甩动时再叠 `(1+bowBoost*1.05)`，快拖手感像被风鼓起来。
- **硬纸板**（封面 / 封底 / 环衬）：`lamMax=.10` + **绕竖轴刚体旋转** + **板厚度面**
  `th = W*.024*|sin(π q)|`（侧立时最厚，读起来是"一叠卡纸"），影子更实
  `A=(hard?.46:.32)*pr`，`KZ=hard?.12:...`（立得更直），缓动指数 `3.0`（软页 4.2）→ 有重量感。
- **`state.kinds`** 由 `buildBookPages()` 打标（`cover/endpaper/title/content/back`），
  `kindAt(i)` 供引擎判定；`sheetHard(i)` 同时看"翻的是哪张"和"下面是哪张"。
- **翻页速度三档**（利落 520 / 标准 820 / 舒缓 1180 ms），面板分段控件，`onChange` 里
  只存盘不重排书页。
- **悬停外下角折角**：`pointermove` 判定「近下边 (`py>top+ph*.82`) + 近书口边 (`d<pw*.16`)」，
  `cornerA` 以 0.20 系数淡入淡出，翻页/拖拽中归零。`drawFold()` 画掀起背面 + 露出下层 + 折痕。

### ② 内页：「干净照片」消除 28 页重复外壳
原先把**模版成品**（套了宝丽来白框 / 杂志页眉的 `art`）直接塞进书页 → 28 页长得一样、
标题重复 28 遍、白框套白框。新增 **`renderPlain(photo)`**：只走调色管线、按**原图比例**出图，
不加任何模版外壳。`artOf(im)` 优先返回 `im.plain`，书里一律用它；
模版成品只留在胶片带与预览区（那里才是"选模版"的地方）。
判据（写进测试）：`art` 外圈是纸、`plain` 外圈是照片，28/28 例成立。

### ③ 内页版式：四版式重排 + 图注锚到固定基线
`renderContent(items,pageNo,W,H,side)` 支持 `full / mat / two / sticker`：
- 图注从"贴照片下缘"改成 **一条短细线 + 一行衬线小字（逐字符字距 `tracked()`）+ 固定基线**
  `capY = H-PB-W*.048`。照片在「上边距 → 图注上方」这个箱体里居中。
  **目的**：竖构图照片几乎填满箱体、图注紧贴；横构图照片居中留白、图注仍落在同一条基线上
  —— 每页架构一致，横构图下方的空白读成「留白」而不是「没排完」。
- 页码 `folio()` 落**书口一侧**（跨页时左页靠左、右页靠右；单页居中），不再居中骑在中间。
- `full` 满版：书沟一侧渐暗 + 天地淡边（否则跨页打开两页"断开"）。

### ④ 封面：自动挑图 + 四段式中轴排版

### 本轮的两个真 bug（都不是外观问题）
1. **`kick()` rAF 链断裂 → 阅读器永久空白。**
   原写 `if(this.raf||!this.cw) return;`。沉浸阅读器容器刚 `display:flex` 时 `layout()`
   量到 `cw=0`，直接 return 且**再没人重新启动** → 画布永远空白。
   修：`cw=0` 先补一次 `layout()`，仍为 0 就下一帧重试（上限 120 次 ≈ 2s）。
2. **`book.speed` 存进去是字符串。** 分段控件 `data-v="3"` 是字符串，`setPath` 原样存，
   之后 `s===3` 全部静默失败、永远落回默认档。修：panel click 处理里
   `v = parseInt(v,10)||2` 显式转型（`book.speed` 不重排书页，也不该重排）。

### 测试脚手架自己造过一次假失败（教训）
