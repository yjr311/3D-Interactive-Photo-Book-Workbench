# 咔哒书 KADA · 项目长期约定

单文件 HTML 照片书工具。源码在 `.workbuddy/tmp/src/`（`head.html` + `core.js` + `photos.js` + `app.js`），
由 `.workbuddy/tmp/build.py` 拼成 `咔哒书-3D互动照片书.html`（零依赖、可 `file://` 打开）。
> 第十轮改名：光匣 LUMEN → 咔哒书 KADA。**代码里的 `window.LUMEN` / 存档 key
> `lumen.prefs.v1` 故意保留**（改前者要把整套回归跟着改，改后者老用户丢存档）。
> 品牌名是常量 `BRAND` / `OLD_BRAND`（core.js 顶部）—— 再改名只动这两行。
**改完源码必须重新 build，产物才是唯一交付物。**

构建带压缩：terser 压 JS（**toplevel 不混淆**，顶层标识符与 `window.LUMEN` 才能存活）+
CSS 只去注释与行首缩进（**行内空白一律不动**，别动 `calc()`）。
`--no-min` 出未压缩版调试。build 结束会打印 head/js/photos 三段 KB 与 1.2MB 预算余量 ——
**加功能后先看这个数**。

## 硬约定

1. **书页画面来源 = `state.book.art`**，`'tpl'`（模版成品，默认）/ `'plain'`（干净照片）。
   默认必须是 `tpl` —— 用户逐张挑的模版必须在成书里看得见，否则模版功能白做。
2. **模版文字一律用占位符**（`{name}` `{n}` `{nn}` `{total}` `{tpl}` `{note}` `{mood}` `{date}`），
   不要在 `state.opts` 里写常量文字：常量会在 28 页上重复 28 遍。
3. **同一信息不出现两次 —— 但判据要比较"内容"，不能比较"存在性"**。
   书页图注的抑制条件是 `plateHasText()`：**印片里是不是写着同一句话**。
   曾经的实现是 `artMode()==='tpl' && !!im.title` —— 而 `opts.title` 出厂就是 `{name}`，
   **每张成片都带非空 title**，于是这个条件恒为真、图注在任何页面上都不画：
   用户选了文案，书里一个字都没有（用户原话「选择了怎么显示出来没效果」）。
   现在的语义：文案 ≠ 印片题字（照片名 vs 一句话）→ 画；
   文案 = 印片题字（`opts.title` 用了 `{note}`，或图注来源选"照片名"）→ 不重复。
   **凡是"有了就不做"的抑制逻辑，都要拿内容比，并且配一条"必须真的做"的测试。**
4. 新增 `book.*` / `opts.*` 键时，同步在 `PERSIST.restore()` 里决定要不要补默认值；
   **改出默认值时必须做定向迁移**（只升级"原样等于旧默认值"的字段），不要换 KEY 版本号。
5. 封面 / 扉页 / 环衬走 `artOf()`（干净照片）；内容页走 `plateOf()`。两者别混。
6. **用户能改的每一项，都要在他最终交付的东西里留下痕迹。** 默认值不能选成"改了也看不见"
   （图注默认 `note` 而不是 `name`、`book.art` 默认 `tpl` 都是这条的产物）。
7. **氛围的唯一写入点是 `applySkin()`**：它必须同时改 `state.opts`（印片）与 `state.book`（书页/书封），
   只改一边就是"书页变粉了、印片还是米色"的割裂。皮肤只给 token，**不复制模版**。
8. **CSS 类名不许撞车**：`.note` 曾被说明段落 `<p class="note">` 与文案候选按钮共用，
   按钮的 `nowrap + overflow:hidden` 把面板里 14 段说明全截成了一行（不报错、不溢出、只是文字消失）。
   组件的类名要带作用域前缀（`.notes .note`）。症状是"文字从句中消失"时，
   第一时间量 `whiteSpace` / `overflow` 与 `scrollWidth > clientWidth`。
9. **铺模版 / 生成成片的顺序必须一致**：`autoBook()` 铺模版的顺序必须与
   `generate()` 里 `filter(picked)` 的顺序完全一致，否则 `generated[i]` 对不上人，逐张改会改错。
10. **"一键"类功能不许开后门**：只允许把面板上已有的动作替用户点一遍，
    点完用户仍能逐项改。绝对不要做一条绕过既有状态、不可回改的旁路。
11. **氛围 = 色号 + 材料 + 题字工艺，三者缺一就是"只换了个色"**。
    用户验收第一版氛围的原话是「单单纯纯的换了个色，没有任何质感」——
    所以任何新的"氛围/皮肤"都必须在 `SKINS[*].mats` 里给材料（`MATSETS` 的键），
    并让 `applySkin()` 一起换掉。**只加配色的氛围不算做完了。**
12. **程序生成的贴图必须"确定性 + 可无缝平铺"**：
    - 确定性：只用 `rng(seed)`，绝不用 `Math.random`。否则每次重排书页纹理都会闪。
    - 无缝：任何特征都要经 `at()` 在 ±256 四个方向补画；**整幅渐变是不可平铺的**
      （丝绸踩过：4 条对角渐变 → 宽页上每 256px 一条竖接缝）。
      连续波要用**整数波数**的正弦（周期正好等于 tile 边长）。
    - 判"可平铺"的度量：**接缝跳变 vs 贴图内部（排除接缝本身）的最大跳变**。
      用"均值"会把帘纹纸每 4 行的正常大跳误判成接缝；忘了排除接缝对则比值恒 ≤1、永远放行。
      **检测器自己也要有反向对照测试**（造一张坏贴图，必须被判为"有接缝"）。
13. **封面二次叠印只对粗料做**（`MAT_TWO_PASS=['linen','canvas','kraft']`）：
    叠两遍是为了搅掉平铺周期，对织纹/纤维有效；但对"连续波"的材料（丝绸）会互相干涉出
    **摩尔纹菱形格**（暗封面上一眼可见）。
14. **材料是"装帧层"，刻意不烧进成片**：换材料只重排书页（`scheduleBook`）、不重新生成、
    也不判过期（`bookSig` 不含 `book.mat`）。它留下的痕迹在书页/书封上，不在每张照片里 ——
    让用户为换一次装帧重等 28 张渲染是错的。
15. **取证脚本要小心"读默认值"**：`pressTreat` 的工艺取自 `state.book.mat` 而不是传进去的参数；
    画对照样张时必须同步设 `state.book.mat`，否则看到的是错的工艺。
    同理真实鼠标点击前要 `scrollIntoView`（面板可滚动，元素可能在视口外 → 点空）。
16. **书页图注必须"四个版式都画得出来"**：`full`（满版出血）原本整段没有画图注的
    代码路径 —— 用户写了文案又选了满版，那句话在整本书里一个字都不出现。
    现在满版也画（底部柔光带 + 白字，位置在页码上方）。**改版式不能让用户的内容消失。**
17. **测试要打到"用户能看见的那一层"**：`test_note` 的 N10 原本只"数图注带里的墨点"，
    而印片和照片本身就有墨 → "根本没画图注"也判成通过（假通过）。
    现在改成**同页"有文案 vs 无文案"的带内像素差**。
    同理 B30 原本断言的是错误语义，已改为"不是同一句话就必须画"。
18. **中文字族必须"探测"，不许让浏览器静默降级。** 零依赖 / 离线 / `file://` 的产物里
    没有 web 字体，中文只能从系统找；而浏览器遇到**不存在的字族不报错**，直接用默认字体顶上
    —— 同一份文件、同一行代码，开发机落到宋体、用户机落到黑体（用户原话
    「显示的字体太板正了……还跟右边显示的字体不一样」就是这么来的：
    左边中文黑体、右边拉丁 Georgia）。
    - 字族按**用途**分角色：`serif` 只给题字（封面/书名页/版权页/导出页眉），
      新增 `cap` 给正文（书页图注，首选楷体），`hand` 给手写体（贴纸版式）。
      **图注是正文不是标题**，别借 `serif`。
    - 开机用 `fontOK(fam)` **位图探测**：同一个"中文 + 拉丁"样本，用该字族 vs
      一个绝对不存在的字族各画一遍，像素有差才算"装了"；挑第一个确实装了的。
      样本必须带拉丁 —— 中文字族的 CJK 可能和系统默认中文一模一样，只看中文会漏判。
      全部验不出来时**不退给 `serif` 去猜**，明确退到界面同一套黑体。
    - **面板把实际用到的字族写出来**（"图注字体 楷体"）。不写出来这件事就是隐形的 ——
      这一行是排查时最缺的信息。
    - 判"用户看到的是哪款字"：从截图反推显示比例（量若干字的像素宽 →
      字号 ≈ 宽 /(字数×1.14) → 与画布宽之比），再用无头浏览器把窗口调到**同一比例**
    （1850×1100 → `BV.pw≈456`）截图对照；并做对照实验排除"JPEG 压缩吃掉细横"。
      **不要凭 1x 截图猜字体** —— 宋体的细横在压缩后仍在，等笔宽才是黑体。
19. **反向对照要覆盖"环境依赖"的分支**：`.workbuddy/tmp/_neg_font.mjs` 把字族改回旧写法
    （N30 挂）、把本机不存在的字族写前面（复刻用户环境 → 中文落黑体 → N28 挂）。
    凡断言涉及"环境里有没有某个东西"，都要造出"没有"的那一支并让它真的失败。
20. **`spineX` 是"缝在哪"，不是"某条边的位置"** —— 它的语义随模式漂移：
    合书时 = 当前页左边；**跨页时 = 书沟**（左页在 `spineX - pw`，右页在 `spineX`）。
    所以凡是要"某一页的某条边"，都必须**显式写 `spineX ± pw`**，不要依赖 `spineX` 此刻是什么。
    折角 bug 就是这条：`drawFold` 里 `right?spineX+pw:spineX` 给左页少了一个 `- pw`，
    于是悬停左页左下角时折角被画到**书沟**上（用户原话「怎么会在那个位置上出现呢」）。
    只有左页会错（右页本来就是 `+pw`），所以症状看着像随机故障。
21. **"位置类"视觉 bug 的取证：开/关两张图的像素差。** 想量"折角落在哪"时，
    "找浅色三角"量不到（那片是渐变，阈值挑不出边界）；改成同一帧 **`cornerOn=true` 与
    `false` 各画一次、取像素差**，差的 bbox 就是它真正的落点（463 vs 99，一眼定案）。
    **能变成一个坐标，才能进回归。**
22. **假绿断言要留反向对照证明"有牙"**：折角那条除了 ④（两侧都必须贴书口边、离开书沟），
    另加 **④b** —— 运行时把锚点还回书沟，同一判据必须判不合格（旧写法 `x∈[468,516]` vs 沟 469）。
    只有 ④ 的话，它有可能只是"恰好通过"。可复现「改前」的办法：
    从**已交付产物**里抽出压缩后的函数体，做一次字符串还原（`spineX-n` → `spineX`），
    运行时 `eval` 覆盖原型方法即可，不必留一份旧 HTML。

23. **品牌名只写一处**（`BRAND` / `OLD_BRAND`，core.js 顶部）。默认值和「改名迁移」必须共用它 ——
    两处各自写死，"默认值改了、迁移里还写着旧名"这种事一定会再发生。
    第十轮改名踩的坑：迁移时把 `title/author/spine` 当成了 `opts` 的字段，
    而它们其实挂在 **`book`** 下面 → `DEFAULT_OPTS.author` 是 `undefined`，
    迁移一跑把字段**抹成 undefined**，症状是**字段从 `JSON.stringify` 里凭空消失**
    （不是值错，是根本没写进去）。**写迁移前先 grep 到定义那一行看清挂在谁下面。**
    另外 `opts.title` 是印片题字（出厂 `{name}`），跟品牌名无关，别碰。
24. **能用 `fill-rule="evenodd"` 表达的形状，不要上 `<mask>`。** 图标"圆角方挖空一本书"
    最初用 mask（白方挖黑书），整块没挖动，排查成本远高于换个做法；
    单路径 evenodd（外框 + 书的子路径）一次就对，语义也更直白。
    附带：**别用 CSS 去覆盖 SVG 的 `fill` 属性** —— `.mk{fill:currentColor}` 把
    `fill="none"` 的描边环一起变成了实心圆盘。要什么就写在该元素的属性上。
25. **"绕某点缩放"必须显式写成 `中心 + 偏移*比例`。** 生成图标路径时写成 `(cx+v)*s`
    等于把中心也乘了一遍，图形被整体推走；而且偏移量不大时**看图很容易误判成"刻意的重心偏移"**。
    正确写法：`sx(v) = cx + v*s`。
26. **单文件零依赖工具里，图标必须纯矢量，不许依赖字体。** 原来的 logo 是"琥珀方块里一个「匣」字"，
    一旦系统没有那个字族就废（见规则 18）。第十轮把它换成挖空的矢量书形，
    顺手把这个环境风险一起解决了。同理 favicon 用 `data:image/svg+xml;base64`（免转义坑）。
27. **用户给参考图时，先把图量出来，再动手画。** 用户拿一张小图说"要类似这种的"，
    他给的是**参数**，不是感觉。第十一轮那张 16px 手绘小鱼，逐像素打印亮度矩阵就反推出了
    描边宽度（7.5%）、描边/填充亮度（60 / 176）、两者比值（2.9）、内部细节条数（2）。
    第一版凭印象画：描边粗 50%、填充亮 47 个百分点、比值 7.4 → 细节全糊。
    **"像不像"这种主观判断，一量就变成可校的数值。**
28. **图标/图形这类"视觉分量"要单独校，不能只校 bbox。** 宽而矮的形状（摊开的书）
    与满格形状（方块）在同一个 29px 盒子里，视觉分量差一截。做法是按 **sx ≠ sy** 缩放
    （本项目 1.055 / 1.17）把形状"变宽变厚"。改路径数字用脚本（`_scale.py`），
    不要手改 —— 手改三十个坐标必错；居中位移用外层 `<g transform="translate()">` 而不是改数字。
29. **判图标只能在真实产物里判。** 自建预览页会失真：第十一轮预览页漏了 `.brand` 外层，
    于是 `.brand .logo{width:29px}` 不命中，图标被渲染成占满整条顶栏（看上去"方案很丑"，
    实际是预览页的 bug）。正确做法：读产物 HTML、正则替换 `<svg class="logo">…</svg>`
    写临时副本（`_mkprev.py`）再截图。**预览页必须复刻目标的真实 DOM 层级，不只是颜色。**
30. **产物在预览面板里打开过就会被写回，"干净原件"和磁盘文件不是一回事。**
    WorkBuddy 的预览会给页面上每个元素插一个 `data-page-node-id="…"`（本项目实测
    **66 处 / +2.8 KB**），而且是**写回磁盘**的 —— 归档的旧产物里也有 64 处，说明一直如此。
    后果：拿磁盘文件量体积会多算 2.8 KB。
    **口径：体积预算一律看 `build.py` 自己打印的数**（它量的是刚拼出来、还没被预览过的字符串）。
    要拿干净原件就重新 build。查污染：`grep -c data-page-node-id 产物.html`，应为 0。
    功能无影响（只是多几个属性），但别拿它做字节级 diff / 哈希比对。
31. **小尺寸可读性要给"内部结构"留对比，不能只留轮廓。** 摊开的书在 16px 下，
    中缝若只有 `1.9@opacity .55`，两个页尖就读成"分开的翅膀"；改成 `2.6@.95` 实心才认得出是书。
    做法：把候选渲成 16px 真实位图再 **8× 最近邻放大**看（`imageSmoothingEnabled=false`），
    别靠大图脑补小图。

## 用正则给源码打补丁

本项目长期用 Python 正则做外科式补丁。踩过一次大坑：替换串只带了两个捕获组、
**没把中间那段要保留的内容带回去**，于是 7 套皮肤的全部配色字段被静默删除，
文件还变短了（看起来像"补丁成功"）。

- 替换串必须把**匹配区间内所有要保留的内容**原样带回去；
  用 `[\s\S]*?` 跨区间匹配尤其危险。
- 补丁后立刻做**值级校验**（比对具体字段的值），不要只看文件大小或 grep 命中。
- **已交付的产物就是最好的备份**：它带着压缩前那份数据的精确值
  （本轮就是靠从产物里反向提取 `SKINS` 字面量、逐字段比对来确认修好的）。
- Git Bash 里用 heredoc 写含反斜杠的正则会**被吃掉转义符**，改用 Write 工具落盘 .py 再跑。
