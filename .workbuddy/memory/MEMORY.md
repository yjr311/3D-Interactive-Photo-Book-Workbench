# 咔哒书 KADA · 项目长期约定

单文件 HTML 照片书工具。源码在 `.workbuddy/tmp/src/`（`head.html` + `core.js` + `photos.js` + `app.js`），
由 `.workbuddy/tmp/build.py` 拼成 `咔哒书-3D互动照片书.html`（零依赖、可 `file://` 打开）。
> 第十轮改名：光匣 LUMEN → 咔哒书 KADA。**代码里的 `window.LUMEN` / 存档 key
> `lumen.prefs.v1` 故意保留**（改前者要把整套回归跟着改，改后者老用户丢存档）。
> 品牌名是常量 `BRAND` / `OLD_BRAND`（core.js 顶部）—— 再改名只动这两行。
**改完源码必须重新 build，产物才是唯一交付物。**

构建带压缩：terser 压 JS（**toplevel 不混淆**，顶层标识符与 `window.LUMEN` 才能存活）+
CSS 只去注释与行首缩进（**行内空白一律不动**，别动 `calc()`）。
`--no-min` 出未压缩版调试。build 结束会打印 head/js/photos 三段 KB 与 1.2MB 预算余量 ——
**加功能后先看这个数**。

## 硬约定

1. **书页画面来源 = `state.book.art`**，`'tpl'`（模版成品，默认）/ `'plain'`（干净照片）。
   默认必须是 `tpl` —— 用户逐张挑的模版必须在成书里看得见，否则模版功能白做。
2. **模版文字一律用占位符**（`{name}` `{n}` `{nn}` `{total}` `{tpl}` `{note}` `{mood}` `{date}`），
   不要在 `state.opts` 里写常量文字：常量会在 28 页上重复 28 遍。
3. **同一信息不出现两次 —— 但判据要比较"内容"，不能比较"存在性"**。
   书页图注的抑制条件是 `plateHasText()`：**印片里是不是写着同一句话**。
   曾经的实现是 `artMode()==='tpl' && !!im.title` —— 而 `opts.title` 出厂就是 `{name}`，
   **每张成片都带非空 title**，于是这个条件恒为真、图注在任何页面上都不画：
   用户选了文案，书里一个字都没有（用户原话「选择了怎么显示出来没效果」）。
   现在的语义：文案 ≠ 印片题字（照片名 vs 一句话）→ 画；
   文案 = 印片题字（`opts.title` 用了 `{note}`，或图注来源选"照片名"）→ 不重复。
   **凡是"有了就不做"的抑制逻辑，都要拿内容比，并且配一条"必须真的做"的测试。**
4. 新增 `book.*` / `opts.*` 键时，同步在 `PERSIST.restore()` 里决定要不要补默认值；
   **改出默认值时必须做定向迁移**（只升级"原样等于旧默认值"的字段），不要换 KEY 版本号。
5. 封面 / 扉页 / 环衬走 `artOf()`（干净照片）；内容页走 `plateOf()`。两者别混。
6. **用户能改的每一项，都要在他最终交付的东西里留下痕迹。** 默认值不能选成"改了也看不见"
   （图注默认 `note` 而不是 `name`、`book.art` 默认 `tpl` 都是这条的产物）。
7. **氛围的唯一写入点是 `applySkin()`**：它必须同时改 `state.opts`（印片）与 `state.book`（书页/书封），
   只改一边就是"书页变粉了、印片还是米色"的割裂。皮肤只给 token，**不复制模版**。
8. **CSS 类名不许撞车**：`.note` 曾被说明段落 `<p class="note">` 与文案候选按钮共用，
   按钮的 `nowrap + overflow:hidden` 把面板里 14 段说明全截成了一行（不报错、不溢出、只是文字消失）。
   组件的类名要带作用域前缀（`.notes .note`）。症状是"文字从句中消失"时，
   第一时间量 `whiteSpace` / `overflow` 与 `scrollWidth > clientWidth`。
9. **铺模版 / 生成成片的顺序必须一致**：`autoBook()` 铺模版的顺序必须与
   `generate()` 里 `filter(picked)` 的顺序完全一致，否则 `generated[i]` 对不上人，逐张改会改错。
10. **"一键"类功能不许开后门**：只允许把面板上已有的动作替用户点一遍，
    点完用户仍能逐项改。绝对不要做一条绕过既有状态、不可回改的旁路。
11. **氛围 = 色号 + 材料 + 题字工艺，三者缺一就是"只换了个色"**。
    用户验收第一版氛围的原话是「单单纯纯的换了个色，没有任何质感」——
    所以任何新的"氛围/皮肤"都必须在 `SKINS[*].mats` 里给材料（`MATSETS` 的键），
    并让 `applySkin()` 一起换掉。**只加配色的氛围不算做完了。**
12. **程序生成的贴图必须"确定性 + 可无缝平铺"**：
    - 确定性：只用 `rng(seed)`，绝不用 `Math.random`。否则每次重排书页纹理都会闪。
    - 无缝：任何特征都要经 `at()` 在 ±256 四个方向补画；**整幅渐变是不可平铺的**
      （丝绸踩过：4 条对角渐变 → 宽页上每 256px 一条竖接缝）。
      连续波要用**整数波数**的正弦（周期正好等于 tile 边长）。
    - 判"可平铺"的度量：**接缝跳变 vs 贴图内部（排除接缝本身）的最大跳变**。
      用"均值"会把帘纹纸每 4 行的正常大跳误判成接缝；忘了排除接缝对则比值恒 ≤1、永远放行。
      **检测器自己也要有反向对照测试**（造一张坏贴图，必须被判为"有接缝"）。
13. **封面二次叠印只对粗料做**（`MAT_TWO_PASS=['linen','canvas','kraft']`）：
    叠两遍是为了搅掉平铺周期，对织纹/纤维有效；但对"连续波"的材料（丝绸）会互相干涉出
    **摩尔纹菱形格**（暗封面上一眼可见）。
14. **材料是"装帧层"，刻意不烧进成片**：换材料只重排书页（`scheduleBook`）、不重新生成、
    也不判过期（`bookSig` 不含 `book.mat`）。它留下的痕迹在书页/书封上，不在每张照片里 ——
    让用户为换一次装帧重等 28 张渲染是错的。
15. **取证脚本要小心"读默认值"**：`pressTreat` 的工艺取自 `state.book.mat` 而不是传进去的参数；
    画对照样张时必须同步设 `state.book.mat`，否则看到的是错的工艺。
    同理真实鼠标点击前要 `scrollIntoView`（面板可滚动，元素可能在视口外 → 点空）。
16. **书页图注必须"四个版式都画得出来"**：`full`（满版出血）原本整段没有画图注的
    代码路径 —— 用户写了文案又选了满版，那句话在整本书里一个字都不出现。
    现在满版也画（底部柔光带 + 白字，位置在页码上方）。**改版式不能让用户的内容消失。**
17. **测试要打到"用户能看见的那一层"**：`test_note` 的 N10 原本只"数图注带里的墨点"，
    而印片和照片本身就有墨 → "根本没画图注"也判成通过（假通过）。
    现在改成**同页"有文案 vs 无文案"的带内像素差**。
    同理 B30 原本断言的是错误语义，已改为"不是同一句话就必须画"。
18. **中文字族必须"探测"，不许让浏览器静默降级。** 零依赖 / 离线 / `file://` 的产物里
    没有 web 字体，中文只能从系统找；而浏览器遇到**不存在的字族不报错**，直接用默认字体顶上
    —— 同一份文件、同一行代码，开发机落到宋体、用户机落到黑体（用户原话
    「显示的字体太板正了……还跟右边显示的字体不一样」就是这么来的：
    左边中文黑体、右边拉丁 Georgia）。
    - 字族按**用途**分角色：`serif` 只给题字（封面/书名页/版权页/导出页眉），
      新增 `cap` 给正文（书页图注，首选楷体），`hand` 给手写体（贴纸版式）。
      **图注是正文不是标题**，别借 `serif`。
    - 开机用 `fontOK(fam)` **位图探测**：同一个"中文 + 拉丁"样本，用该字族 vs
      一个绝对不存在的字族各画一遍，像素有差才算"装了"；挑第一个确实装了的。
      样本必须带拉丁 —— 中文字族的 CJK 可能和系统默认中文一模一样，只看中文会漏判。
      全部验不出来时**不退给 `serif` 去猜**，明确退到界面同一套黑体。
    - **面板把实际用到的字族写出来**（"图注字体 楷体"）。不写出来这件事就是隐形的 ——
      这一行是排查时最缺的信息。
    - 判"用户看到的是哪款字"：从截图反推显示比例（量若干字的像素宽 →
      字号 ≈ 宽 /(字数×1.14) → 与画布宽之比），再用无头浏览器把窗口调到**同一比例**
    （1850×1100 → `BV.pw≈456`）截图对照；并做对照实验排除"JPEG 压缩吃掉细横"。
      **不要凭 1x 截图猜字体** —— 宋体的细横在压缩后仍在，等笔宽才是黑体。
19. **反向对照要覆盖"环境依赖"的分支**：`.workbuddy/tmp/_neg_font.mjs` 把字族改回旧写法
    （N30 挂）、把本机不存在的字族写前面（复刻用户环境 → 中文落黑体 → N28 挂）。
    凡断言涉及"环境里有没有某个东西"，都要造出"没有"的那一支并让它真的失败。
20. **`spineX` 是"缝在哪"，不是"某条边的位置"** —— 它的语义随模式漂移：
    合书时 = 当前页左边；**跨页时 = 书沟**（左页在 `spineX - pw`，右页在 `spineX`）。
    所以凡是要"某一页的某条边"，都必须**显式写 `spineX ± pw`**，不要依赖 `spineX` 此刻是什么。
    折角 bug 就是这条：`drawFold` 里 `right?spineX+pw:spineX` 给左页少了一个 `- pw`，
    于是悬停左页左下角时折角被画到**书沟**上（用户原话「怎么会在那个位置上出现呢」）。
    只有左页会错（右页本来就是 `+pw`），所以症状看着像随机故障。
21. **"位置类"视觉 bug 的取证：开/关两张图的像素差。** 想量"折角落在哪"时，
    "找浅色三角"量不到（那片是渐变，阈值挑不出边界）；改成同一帧 **`cornerOn=true` 与
    `false` 各画一次、取像素差**，差的 bbox 就是它真正的落点（463 vs 99，一眼定案）。
    **能变成一个坐标，才能进回归。**
22. **假绿断言要留反向对照证明"有牙"**：折角那条除了 ④（两侧都必须贴书口边、离开书沟），
    另加 **④b** —— 运行时把锚点还回书沟，同一判据必须判不合格（旧写法 `x∈[468,516]` vs 沟 469）。
    只有 ④ 的话，它有可能只是"恰好通过"。可复现「改前」的办法：
    从**已交付产物**里抽出压缩后的函数体，做一次字符串还原（`spineX-n` → `spineX`），
    运行时 `eval` 覆盖原型方法即可，不必留一份旧 HTML。

23. **品牌名只写一处**（`BRAND` / `OLD_BRAND`，core.js 顶部）。默认值和「改名迁移」必须共用它 ——
    两处各自写死，"默认值改了、迁移里还写着旧名"这种事一定会再发生。
    第十轮改名踩的坑：迁移时把 `title/author/spine` 当成了 `opts` 的字段，
    而它们其实挂在 **`book`** 下面 → `DEFAULT_OPTS.author` 是 `undefined`，
    迁移一跑把字段**抹成 undefined**，症状是**字段从 `JSON.stringify` 里凭空消失**
    （不是值错，是根本没写进去）。**写迁移前先 grep 到定义那一行看清挂在谁下面。**
    另外 `opts.title` 是印片题字（出厂 `{name}`），跟品牌名无关，别碰。
24. **能用 `fill-rule="evenodd"` 表达的形状，不要上 `<mask>`。** 图标"圆角方挖空一本书"
    最初用 mask（白方挖黑书），整块没挖动，排查成本远高于换个做法；
    单路径 evenodd（外框 + 书的子路径）一次就对，语义也更直白。
    附带：**别用 CSS 去覆盖 SVG 的 `fill` 属性** —— `.mk{fill:currentColor}` 把
    `fill="none"` 的描边环一起变成了实心圆盘。要什么就写在该元素的属性上。
25. **"绕某点缩放"必须显式写成 `中心 + 偏移*比例`。** 生成图标路径时写成 `(cx+v)*s`
    等于把中心也乘了一遍，图形被整体推走；而且偏移量不大时**看图很容易误判成"刻意的重心偏移"**。
    正确写法：`sx(v) = cx + v*s`。
26. **单文件零依赖工具里，图标必须纯矢量，不许依赖字体。** 原来的 logo 是"琥珀方块里一个「匣」字"，
    一旦系统没有那个字族就废（见规则 18）。第十轮把它换成挖空的矢量书形，
    顺手把这个环境风险一起解决了。同理 favicon 用 `data:image/svg+xml;base64`（免转义坑）。
    **现状（第十二轮定稿）**：手绘小书 —— 顶栏 `<svg class="logo">` 与 favicon 用同一份几何
    （贪方便把同一段路径常量在 `_patch_logo.py` 里展开成两处，改一处必须改两处；产物里
    新路径出现 **3 次**、旧方块路径必须出现 **0 次**，`test_book` 的 B41/B45 就盯这个）。
27. **用户给参考图时，先把图量出来，再动手画。** 用户拿一张小图说"要类似这种的"，
    他给的是**参数**，不是感觉。第十二轮那张 16px 手绘小鱼，逐像素打印亮度矩阵就反推出了
    描边宽度（7.5%）、描边/填充亮度（60 / 176）、两者比值（2.9）、内部细节条数（2）。
    第一版凭印象画：描边粗 50%、填充亮 47 个百分点、比值 7.4 → 细节全糊，用户就是这时说"不好看"的。
    **"像不像"这种主观判断一量就变成可校的数值；改数字能收敛，改"感觉"不能。**
28. **图标/图形这类"视觉分量"要单独校，不能只校 bbox。** 宽而矮的形状（摊开的书）
    与满格形状（方块）在同一个 29px 盒子里，视觉分量差一截。做法是按 **sx ≠ sy** 缩放
    （本项目 1.055 / 1.17）把形状"变宽变厚"。改路径数字用脚本（`_scale.py`），
    不要手改 —— 手改三十个坐标必错；居中位移用外层 `<g transform="translate()">` 而不是改数字。
29. **判图标只能在真实产物里判。** 自建预览页会失真：第十二轮预览页漏了 `.brand` 外层，
    于是 `.brand .logo{width:29px}` 不命中，图标被渲染成占满整条顶栏（看上去"方案很丑"，
    实际是预览页的 bug）。正确做法：读产物 HTML、正则替换 `<svg class="logo">…</svg>`
    写临时副本（`logo/_mkprev.py`）再截图。**预览页必须复刻目标的真实 DOM 层级，不只是颜色。**
    （改前/改后对照同理走真产物：用改图标前的 `_bak_head2.html` 拼一份 `_oldlogo.html`，
    于是两张图是"同一份产品、只差图标"。）
30. **产物在预览面板里打开过就会被写回，"干净原件"和磁盘文件不是一回事。**
    WorkBuddy 的预览会给页面上每个元素插一个 `data-page-node-id="…"`（本项目实测
    **66 处 / +2.8 KB**），而且是**写回磁盘**的 —— 归档的旧产物里也有 64 处，说明一直如此。
    后果：拿磁盘文件量体积会多算 2.8 KB。
    **口径：体积预算一律看 `build.py` 自己打印的数**（它量的是刚拼出来、还没被预览过的字符串）。
    要拿干净原件就重新 build。查污染：`grep -c data-page-node-id 产物.html`，应为 0。
    功能无影响（只是多几个属性），但别拿它做字节级 diff / 哈希比对。
31. **"设置 → 渲染 → 文件"的链路，断言必须打在最末端。** 第十一轮的"发布尺寸没效果"：
    `test_export` 的 E5/E8 断言的是**设置变了**（`spec.ratio==='3:4'`、`bookStale()===true`）——
    一直是绿的；而用户报的是**文件没变**。断言停在"用户能看见的那一层"的**上一站**，
    于是 bug 活了很多轮。补的断言直接跳到终点：**解包 ZIP、读字节里的真实像素**。
    凡是导出/下载/落盘类功能，都要有一条"读产物本身"的断言。
32. **凡"导出/下载"，落盘的必须比设置新，命名必须比设置诚实。**
    产品侧的两条硬规则（缺一不可）：
    ① 导出前用 `bookStale()` 守门，过期就**替用户点一遍「生成成片」再打包**
       （不是旁路，符合规则 10），`exportZip` / `exportCurrent` 都走；
    ② **命名与说明一律从产物读**（`canvas.width`），只在"声明值 === 实际值"时才显示预设名。
    第①条保证发的是新图，第②条保证**即使第①条哪天失效，文件名也不会说谎**。
    另：行为改了，面板文案和 toast 必须跟着改，否则等于把用户支到别处。
    查这类 bug 的手法：在页面里替换 `URL.createObjectURL` 拦 blob →
    扫 Local File Header + `DecompressionStream('deflate-raw')` 解压 → 读 JPEG 的 `SOF` 拿真实像素。
33. **小尺寸可读性要给"内部结构"留对比，不能只留轮廓。** 摊开的书在 16px 下，
    中缝若只有 `1.9@opacity .55`，两个页尖就读成"分开的翅膀"；改成 `2.6@.95` 实心才认得出是书。
    做法：把候选渲成 16px 真实位图再 **8× 最近邻放大**看（`imageSmoothingEnabled=false`），
    别靠大图脑补小图。
34. **品牌图标不跟强调色走（`currentColor` 是坑）。** 被换掉的那版 `fill="currentColor"`，
    于是切浅色主题 / 换氛围皮肤时整枚图标跟着变色 —— **品牌色如果是"当前皮肤色"，它就不成其为品牌色了**。
    现在的图标固定暖棕（`#eec9a4→#d7a578` + `#4a2708`），像一枚贴在界面上的实物贴纸。
    配套：顶栏投影别用强调色的光晕（`0 5px 15px var(--glow)`），换中性 `0 2px 5px rgba(0,0,0,.34)`。
35. **内联 SVG 的 `id` 必须逐份唯一。** `linearGradient id="kadaLogoG"` 被复制到多个文档/页面时，
    浏览器只认第一份 —— 改一份的 stop，另一份跟着变（或不变），排查方向会完全跑偏。
36. **"对照图"的公平性来自同一取景，不是事后对齐。** 改前/改后必须**同窗口、同 zoom、同裁切框**
    （本项目：同一产物、同一 3× zoom、品牌块同为 `l:42 t:36 87×87` 设备像素，于是可以硬裁同一个矩形）。
    另：拼图脚本给末排文字留的边距要够 —— 第一版把最后一排说明画到了画布外（看着像被截断）。
37. **Git Bash 会吃掉命令行里的中文参数。** 同一个中文文件名，`ls 咔哒书*.html` 会 glob 不中、
    `mv 咔哒书-X.html …` 报 "cannot stat"，而 Python `os.listdir` 明明看得见。**文件操作走 Python**
    （`shutil.move` / `io.open`），脚本里的路径**写死在文件里**而不是从 argv 传。
    同理 heredoc 里的反斜杠会被吃掉（见下节）。
38. **`null`（从没设过）和 `''`（用户清空）不是一个意思 —— 规则 6 在第二批第二次应验。**
    带字贴纸的 `s.text` 写成 `s.text==null||s.text===''` 就把两者混成一个：用户把日期戳的字删光、
    一松手又跳回默认值，**又是"改了却看不见"**。只有 `null` 才回退 `dflt`；加贴纸的那一刻就把默认文字
    **显式写进数据**。同一个错误在 `drawSticker` 里还藏着第二份（`s.text||def.dflt`）——
    修完第一处、测试立刻红在第二处：**同一语义只看一处不够。**
39. **局部变量别用单字母大写去接数字：本项目 `R = Math.round` 是全局的**（core.js:5，`const R=n=>Math.round(n)`）。
    `stkAnniv` 里 `const R=S*.70` 让后面的 `R(size)` 变成"调用一个数字" → 一画纪念日戳就崩。
    它平时不崩，是因为**面板每个小样都包在 try/catch 里**：那一格一直是一片空白，谁都没发现。
    → **凡被 `try{}catch{}` 包住的绘制，坏掉时是"安静地少一块"，必须在别处真画一次才算测过。**
    同族：`R` 是**四舍五入不是取整** —— 拿 `R(i/3)` 当九宫格行索引，i=2→行1、i=8→行3，
    9 格铺成 2/3/3/1、第 9 格跑出版心。行/列索引一律 `Math.floor`。
40. **贴纸挂在"照片坐标"上，并且烧进成片。** 每枚 `{k,x,y,rot,s,text}`，`x/y` 是相对照片的 0..1
    （存时夹到 −0.25..1.25，允许压边半出画）。一份数据同时喂缩略图/胶片/成片/书页/分享长图，
    换画幅不用换算表。**必须烧进成片（`renderCanvas` + `renderPlain`），不能只做书页上的一层**：
    书页有 `art='tpl'|'plain'` 两态、封面还会另挑照片 —— 只画在书页上的贴纸一"切干净照片"就凭空消失。
    代价：**新鲜度必须看得见贴纸** —— `generate()` 存 `stick:stickerSig(p)`、`bookStale()` 比它，
    否则贴完贴纸书页一直是旧的（又一个"改了却看不见"）。
41. **"照片比例的画布"是必需品，不是装饰 —— 但"照片比例"这个做法本身是错的（第十四轮已推翻）。**
    贴纸坐标是照片相对的，它出现在页面哪里却由版式决定；没有这块预览，用户就是**盲贴**。
    ⚠ 但第十三轮把落点乘的是**画布**尺寸（`cx = s.x*W`），于是模版一给照片留白内缩就整体偏
    （实测 `polaroid` 照片矩形 `72,-3,816,1088` vs `magazine` `0,0,960,1280`）。
    现在**面板画布画的就是这张照片的成片（含模版）**，落点一律锚在**照片矩形**上，见 45/46。
    指针事件仍挂 **document**（不挂 canvas）：`renderPanel()` 每次重建 canvas，挂元素上的监听器会随之消失；
    拖动中不写存档，松手才 `PERSIST.save()`；`input` 里**绝不重渲面板**（焦点丢失）。
42. **一键类功能不许推荐"不适合它"的选项。** 九宫格 `grid` **刻意不进任何 `SKINS[*].rec.layout/alts`** ——
    一键成书是给"不想做决定的人"用的，28 张铺成九宫格联系表不是相册。它是**用户可主动选、但不被推荐**的第五种版式。
    守它的两条断言要一起写：**0 套皮肤推荐它** ∩ **它确实在 `LAYOUTS` 里**（只写前一条，删掉 `grid` 也能"通过"）。
43. **探针自己先要有分辨力（第十三轮最贵的教训）。**
    - **量贴纸几何必须在"填白的画布"上量。** 样例照片是深色抽象渐变，"深色像素 bbox"恒等于整张画布 ——
      "涂鸦变宽了"和"什么都没变"量出来一模一样，两个相反结论都能"通过"。
    - **画布里有 `Math.random`（封底条形码是全篇唯一一处）时，位置量测 = "两次渲染求差" + "只取第一段连续差异行"**
      （允许空 `H*.03` 的间隙）。否则随机条码把差异带拖到页脚，"一句话"的 bbox 变成整页。
      间隙写 6px 会把三行寄语砍成第一行（假失败"18px→19px"）；真实行距约 13px、到条码 130+ 行，3% 分得干净。
44. **两条小口径，本轮都真实误报过。** ① **滑杆容差 = 控件自己的 step**：`input[type=range]` 会把 `value`
    吸附到 `step=0.01`，拿 `1e-6` 比就报"滑杆 0.7 / 数据 0.7006"。② **改动之后再读的值，不是"那次改动之后"的值**：
    「加到上限」的循环跑完才读数量 → 得到"0 → 6 枚"而不是"0 → 1"（应在首次点击后立刻取）；
    假定 `goto()` 重载后仍停在第 2 步（实际回第 1 步）→ 拿到 `null`。**同形状的错误出现两次，就该写成一条规则。**
45. **坐标系必须唯一，而且"归一化到什么"要连"从哪块矩形还原"一起定。** 第十四轮的根因就是只做了前半句：
    数据是"照片相对"的（含义对），落点却乘画布尺寸（还原错）。改法：
    `drawFit()`/`paintPhoto()`**返回**实际画照片的那块 `{dx,dy,dw,dh}`，`renderCanvas`/`renderPlain`
    把它挂在 `c.photoRect` 上离开；锚点 = `dx + x*dw`，基准尺寸 = `min(dw,dh)*0.20`。
    `drawSticker(x, rect, s, i, im)` **只收矩形**，**刻意不给 `(W,H)` 数字留兼容重载** ——
    留着就等于承认"两套坐标系"合法，下次一定有人在面板里按画布算。调用方必须写 `{dx:0,dy:0,dw:W,dh:H}`。
    ⚠ 改签名的代价：漏改的调用点会变成 `undefined` → 坐标全 `NaN` → **一个像素都不画**；
    症状是 `-1000000001`（`maxX-minX = -1-1e9` 哨兵值）。**看到量级离谱的数，先查"是不是什么都没画"，别调阈值。**
46. **派生位图不能靠用户点按钮。** 成片是贴纸的下游产物：任何一处改了贴纸，下游必须自动跟上。
    `refreshStickerArt(p)` 只重出**这一张** + 更新 `stick` 签名（`bookStale()` 因此立刻为假）；
    `scheduleArt(p)` 120ms 去抖攒批 → `scheduleBook()`/`schedulePreview()` + `renderDock()` + `PERSIST.save()`。
    **所有改动点都要走这条路**（贴上/拖动/删一枚/清空这一张/清空全部/改文字，六个），留一个就还是"改了却看不见"。
    **不要图省事调 `generate()`**：它会重建 `state.generated`、重置 `_genSig`，还可能把用户切到别的步骤 ——
    那是副作用不是刷新。实测成本：`refreshStickerArt` 29ms / `buildBookPages`(34页) 89ms / `BV.setPages` 41ms。
    拖动时的跟手反馈走**底片缓存**（`stkBaseSig(p)` = `id|name|tpl|zoom|ox|oy|rot|spec|skin|opts|adj`），
    **缓存签名必须覆盖全部输入**，少一项就会出现"换了模版换了皮肤，底片还是旧的"。
47. **指针换算两步，不是一步。** `客户端px →(÷显示尺寸×画布px)→ 画布px →(−矩形原点)÷矩形尺寸→ 归一化`。
    少掉中间那一步在"照片铺满画布"时碰巧对，一有内缩就散 —— 这就是用户说的"位置对不上"的另一半。
    测试里想瞄准 `(.u,.v)` 也要先反算（`at(u,v)` 用 `stkStageRect()`），否则复现不出用户的场景。
48. **检测器自己会造出"产品很慢"。** 第一版延迟检测器每 30ms 调一次 `buildBookPages()`
    （每次新建约 40 张 880×1173 画布）→ 主线程被分配/回收拖住，量到 **1412ms**，
    而页面内里程碑只有 **170/369ms**（差 2~5 倍）。
    两条通用做法：① **延迟断言不用轮询墙钟，用页面内里程碑时间戳**
    （`rAF` 检测对象被换掉 + 包一层 `BV.setPages` 检测书页拿到新页）；
    ② **检测器读"屏幕上真在显示的东西"** —— `L.BV.pages`（画布数组）+ `L.BV.kinds`（类型），
    只哈希不重排；而且它证明的是"屏幕换了"，比"再排一遍会不一样"更硬。
    ⚠ `BV.pages` 存的是**画布**不是页对象，画布上没带页码 → 只能"找第一个内容页"，不能按 `.no` 找。
49. **"字形居中"不是判定锚点的好标准；用平移对照 + 归一化偏移散布。** 心形的墨**天生**比锚点低
    `0.086·S`（8 枚全量：`stamp/anniv/ticket` −0.003、`spark` +0.039/+0.008、心形 −0.003/+0.086）——
    是**字形路径**的偏心，不是坐标算错。拿"绝对居中"当标准会把好代码判死。正确的两条：
    ① **平移多少就挪多少**（矩形挪 `(137,221)`，墨迹中心必须挪 `(137,221)`；与字形无关，把锚点公式钉死）；
    ② **偏移按 S 归一化后跨矩形一致**（三块不同矩形 `du/dv` 散布 < 0.01）；水平方向心形左右对称，可以要求绝对居中。
50. **怀疑"定时器被节流"之前先量一下。** 一度把 1412ms 归因于后台标签页把 `setTimeout(30)` 钳到 1s
    （`document.hasFocus()` 确实是 `false` 很像是证据）。实测 `setTimeout(30/40/120)` = **31/41/121ms**，
    反复静置后也一样；`visibilityState` 是 `visible` —— **假说被自己的数据否掉**。
    顺手记：同一次排查里 `setInterval(1)` 采样器本身被饿死（报出 933ms 空档，其间其实有任务在跑），
    **采样器自身也会说谎**，权威工具是 `PerformanceObserver` 的 `longtask`。

51. **一个值的「坐标系」要在它出生的地方说清楚（第十五轮牛皮纸）。** `paintPhoto` 返回矩形，
    却从没说"在哪个坐标系里" —— 于是它有了两个消费者（`cx.paint` / `renderPlain`，都按**画布像素**理解）
    和一个**含义不同的生产者**：牛皮纸是先 `translate(W/2,H*.45); rotate(-.028)` 再 `c.paint(-pw/2,-ph/2,…)`，
    量出来的矩形是**局部坐标**（实测 `-345.6,-460.8`，960×1280 下 3/4 在画布外、中心压在左上角）。
    面板换算 `clamp((px-rc.dx)/dw,0,1)` → 往右/往下算出来超 1 → 被夹住 → **纹丝不动**，
    只有左上方向能动（用户原话：「插入的贴纸无法往右以及往下拖拽」）。
    修法 `rectThruM(rc, ctx.getTransform())`：四个角过一遍**绘制那一刻的 CTM** 取外接矩形。
    三条纪律：① **CTM 是单位矩阵时原样返回**（绕一圈会带进浮点噪声，而下游有"严格 `>` 挑面积最大者"
    这种把噪声当信号的判据）；② **不返回矩阵**（返回矩阵 = 给"两套坐标系"开后门，见规则 45）；
    ③ 代价是四角最多差 `半宽×sinθ`（牛皮纸 1.6° → 1.6%），但**旋转下矩形中心不变**，
    所以 `(.5,.5)` 仍然精确 —— 那正是最要紧的一格。
52. **要验的不变量必须对「全部变体」成立，不是对你怀疑的那一个。** 静态扫 11 个模版的 `draw()`
    确实抓到了牛皮纸（唯一在 `paint` 前有 `translate/rotate` 的），但**漏了**双色（压根不调 `c.paint`）
    和九宫格（平局）。真正的做法：**让 11 个模版各自渲一遍、把 `photoRect` 打成一张表**
    （`_probe_kraft.mjs`），再对这张表下一条**近乎废话的结构性判据**（"矩形必须落在画布内"）——
    表一打出来谁不对劲自己就跳出来。修前 **8/11** 个模版有病（`kraft`/`polaroid`/`postcard` 越界，
    `neon`/`minimal`/`cinematic` 被 cover 溢出撑大，`duotone` 退化，`grid9` 跳格）。
    **判据自己也要有反面对照**：把修前的值喂给同一条判据，必须判不合格。
53. **"面积最大者胜"这类比较要带容差。** 九宫格画 9 格，9 格的面积**差在 1e-6 px² 以下**，
    严格 `>` 会让"比前者大亿分之几"的格子胜出 —— **赢家由舍入决定，不由设计决定**。
    加 `1e-6` 容差把它钉成"先来先得"（实测：去掉容差赢家从 `352.6,184` 跳到 `623.7,455`）。
    ⚠ **它在一个版本里是确定的**（同代码连渲 12 次同值）—— 所以"连渲 N 次对比"这条检测器**抓不到它**，
    抓它的是"把容差拿掉、看赢家会不会换格"。
    **同一个数"当坐标用"和"当尺子用"，容差要求完全不同**：`drawFit` 的返回值 3 个消费者里，
    `renderPlain` 拿它当坐标（差 0.001px 无所谓）、`makeDuotone` 直接忽略它、
    而 `cx.paint` 拿它**比面积** → 浮点噪声于是变成了产品行为。
54. **cover 溢出的那一圈不是照片。** `paint(x,y,w,h)` 是"铺满这个框、多出来的裁掉"，
    所以**可见照片 = 铺出来的矩形 ∩ 画框**，`paintPhoto` 里必须求交。不求交的后果（实测溢出量）：
    明信片上下各 **158px**、电影感 173、霓虹 136、极简 64、宝丽来 3 ——
    贴纸在这些边上会飘到照片外面，而面板画的虚线还写在"照片边界"上，自相矛盾。
    （`contain` 时矩形本来就小于画框，求交是恒等变换，不会误伤。）
55. **模版不一定走 `c.paint` —— 所以要有一个"申报"的口子。** 双色自己 `makeDuotone()` 重着色之后
    `ctx.drawImage`，于是**没人吭声** → `photoRect` 退化成"整块画布"，贴纸锚在画布中心而不是照片中心
    （**偏 90px**）。补法是给 `cx` 加 `declare(x,y,w,h)`：语法糖而已，语义是"照片就占这个框"，
    不再跑一次 fit 计算 —— 让"我自己贴上去的照片"也能进入同一个坐标系。
56. **同时改多处时，必须做"隔离实验"。** 这一轮同时动了四处（CTM / 与画框求交 / 1e-6 容差 / `declare`），
    一张"改前 vs 改后"的对照说不清哪条修好了什么。造"**只坏一处**"的产物（`_tolon.html` 只去容差、
    `_nointer.html` 只去求交）+ `_before.html`（全去）跑同一张表，才确认：
    牛皮纸只被 CTM 影响，明信片/霓虹/极简/电影感/宝丽来只被"求交"影响，九宫格只被容差影响，
    双色只被 `declare` 影响 —— **四处改动各有各的靶子，一处都没白改**。
    （做法：`.workbuddy/tmp/_mkbefore.py` / `_mkvariants.py` 直接在压缩产物上做字面量替换造残缺产物，
    比回退源码再 build 快得多；替换后必须做**值级校验** + 反面对照。）
57. **新断言必须能判"坏" —— 打回「改前」产物跑一遍。** 把 `test_batch2` 指到 `_before.html`，
    新增的 12 条里有 **9 条失败**（含"往右/往下拖不动"两条本身）。不跑这一步，
    "404 项全绿"什么都不能证明（规则 43 的第四次应验，但这次的失灵方式是新的一种：
    不是阈值不对，是**量错了对象** —— "连渲 N 次"量的是确定性，而这里的病是"**确定的错值**"）。

## 用正则给源码打补丁

本项目长期用 Python 正则做外科式补丁。踩过一次大坑：替换串只带了两个捕获组、
**没把中间那段要保留的内容带回去**，于是 7 套皮肤的全部配色字段被静默删除，
文件还变短了（看起来像"补丁成功"）。

- 替换串必须把**匹配区间内所有要保留的内容**原样带回去；
  用 `[\s\S]*?` 跨区间匹配尤其危险。
- 补丁后立刻做**值级校验**（比对具体字段的值），不要只看文件大小或 grep 命中。
- **已交付的产物就是最好的备份**：它带着压缩前那份数据的精确值
  （本轮就是靠从产物里反向提取 `SKINS` 字面量、逐字段比对来确认修好的）。
- Git Bash 里用 heredoc 写含反斜杠的正则会**被吃掉转义符**，改用 Write 工具落盘 .py 再跑。
